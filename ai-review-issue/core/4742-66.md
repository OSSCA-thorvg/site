## 이슈 요약

이 issue는 core engine 저장소의 `tools/` 아래에서 함께 관리하던 `svg2png`와 `lottie2gif`를 전용 CLI 저장소로 분리하는 작업이다. 목표는 engine source, test와 필수 example만 core에 남기고, command-line utility는 자체 dependency, build, release와 신규 도구를 독립적으로 운영하게 만드는 것이다.

2026-08-30 기준 체크리스트 7개 중 다음 5개는 완료 표시돼 있다.

- 전용 저장소 생성
- `svg2png` source migration
- `lottie2gif` source migration
- 독립 build configuration
- 관련 문서와 link 갱신

남은 항목은 core 저장소에서 도구 source와 불필요한 build option/dependency를 제거하는 일, 그리고 “Godot SVG regressions tests”를 Pixel Inspector로 옮기는 일이다. current main은 README만 새 CLI 저장소로 연결했으며 `tools/`, `-Dtools` Meson option, 도구를 사용하는 build와 SVG regression workflow는 아직 유지한다.

별도 저장소에 복사된 실제 converter source blob은 current main의 source와 동일하다. 따라서 기능을 새로 구현하는 issue라기보다 소유권과 release 경계를 재정의하는 migration이다. 위험은 code copy보다 이전 위치를 제거하는 순간에 발생한다. 새 저장소가 스스로 build/test되지 않거나 기존 regression suite가 동등한 대체 없이 삭제되면 책임만 분리되고 품질 보장은 약해질 수 있다.

## main 코드 조사

current main의 root Meson은 [`tools` option에서 `all`, `svg2png`, `lottie2gif`를 계산](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/meson.build#L49-L52)한다. 이 값은 단순 executable 선택에 그치지 않고 [`svg2png`이면 SVG loader, `lottie2gif`이면 Lottie loader와 GIF saver를 암묵적으로 활성화](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/meson.build#L54-L69)한다. 도구 제거 후에는 loader/saver가 자신의 option에 의해서만 켜지므로 기존 `-Dtools=lottie2gif` build가 같은 library feature를 만들지 않는다.

build graph도 [core library 다음에 `subdir('tools')`를 항상 방문](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/meson.build#L178-L186)하고, configure summary에 [두 tool 활성 상태를 별도 section으로 출력](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/meson.build#L243-L250)한다. 공개 Meson option은 [`svg2png`, `lottie2gif`, `all`을 choice로 제공](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/meson_options.txt#L40-L44)하므로 제거는 source tree 정리이면서 build interface 변경이다.

도구 source migration은 내용 기준으로 확인할 수 있다. current main의 [`svg2png.cpp`](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/tools/svg2png/svg2png.cpp)와 [새 저장소의 `svg2png.cpp`](https://github.com/thorvg/thorvg.cli-tools/blob/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/src/svg2png/svg2png.cpp)는 같은 Git blob을 사용한다. `lodepng.cpp`, `lodepng.h`와 [`lottie2gif.cpp`](https://github.com/thorvg/thorvg.cli-tools/blob/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/src/lottie2gif/lottie2gif.cpp)도 양쪽 blob SHA가 같다. 즉 migration 시점의 code divergence는 없고, 달라진 부분은 build integration이다.

새 CLI 프로젝트의 root Meson은 [먼저 `thorvg-1` dependency를 찾고 없으면 `thorvg`로 fallback](https://github.com/thorvg/thorvg.cli-tools/blob/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/meson.build#L1-L13)한다. core 설치는 실제로 [`thorvg-1` pkg-config file과 Meson dependency override를 생성](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/src/meson.build#L70-L98)하므로 주 경로는 서로 맞는다. 새 프로젝트는 [기본적으로 두 tool을 모두 선택](https://github.com/thorvg/thorvg.cli-tools/blob/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/meson_options.txt#L1-L7)하고 각 executable을 설치 대상으로 만든다.

하지만 dependency discovery만으로 설치된 library가 필요한 module을 포함했는지는 알 수 없다. 새 README도 `lottie2gif`에는 Lottie loader와 GIF saver가, `svg2png`에는 SVG loader가 필요하다고 [명시](https://github.com/thorvg/thorvg.cli-tools/blob/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/README.md#build-and-installation)한다. current API/library metadata는 이 optional feature 조합을 pkg-config requirement로 표현하지 않는다. feature가 빠진 ThorVG에 link하거나 실행했을 때 사용자에게 어떤 configure-time/runtime 오류를 줄지 smoke test가 필요하다.

새 CLI 저장소의 workflow directory에는 [PR labeler 하나만 존재](https://github.com/thorvg/thorvg.cli-tools/tree/8e45bdf62a3c5f4aac575b34ead329ed7d36abb9/.github/workflows)하고 converter build, install 또는 output test workflow는 아직 없다. 반면 current core의 Ubuntu, Windows, macOS workflow는 각각 [`-Dtools=all`로 두 executable을 core와 함께 build](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/.github/workflows/build_ubuntu.yml#L24-L35)한다. legacy source를 제거하면 이 platform coverage도 새 저장소에서 명시적으로 이어받아야 한다.

current README는 이미 [두 converter를 새 CLI 저장소의 “CLI Tools”로 연결](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/README.md#L527-L528)한다. 문서상 소유권은 이동했지만 current main build에서는 아직 core option으로도 설치할 수 있는 과도기 상태다.

가장 큰 검증 경계는 SVG regression workflow다. 이 workflow는 [PR build에 ASan/UBSan과 두 tool을 켜고 current main build도 별도로 준비](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/.github/workflows/svg_regression.yml#L18-L38)한다. 이어 외부 SVG Regression Finder의 valid/not-valid corpus를 내려받아 [crash, leak, timeout과 PR-vs-main image comparison을 실행](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/.github/workflows/svg_regression.yml#L40-L68)한다. comparison 설정은 [400px render, 최대 차이 5, 전체 file 수 무제한과 두 executable path](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/test/regression/settings_comparison.toml#L1-L38)를 계약으로 둔다.

같은 workflow는 한 SVG를 서로 다른 thread scheduling 아래 500회 변환하는 [PNG 재현성 검사](https://github.com/thorvg/thorvg/blob/e43bc8ba922f48f660caedb051346ad7de629bd4/.github/workflows/svg_regression.yml#L148-L160)도 수행한다. 이는 고정 image의 golden diff와 다른 data-race 탐지 목적이다.

Pixel Inspector는 [SVG·Lottie와 등록된 draw test를 backend별 golden image와 비교](https://github.com/thorvg/thorvg.pixel-inspector/blob/1bc12b7c3b970291125f6b76f9f6f8765809eeb5/README.md#features)하며 RGBA Chebyshev distance와 diff ratio threshold를 제공한다. current corpus에는 Godot icon을 포함한 고정 SVG fixture가 있지만, 외부 valid/not-valid archive 전체를 매번 내려받는 구조나 sanitizer crash/leak/timeout 분류, 500회 scheduling 재현성 검사는 문서상 제공하지 않는다.

이 issue를 가리키는 열린 [legacy 제거 PR](https://github.com/thorvg/thorvg/pull/4745)은 tool source, Meson option, OS build의 `-Dtools`, SVG regression workflow와 설정 파일을 한 번에 삭제한다. 해당 PR의 Pixel Inspector 보고는 GL/WGPU/SW 각각 497개 비교에서 차이와 오류가 0이라고 확인하지만, 이것은 삭제되는 dynamic corpus·sanitizer·반복 실행 coverage의 동등성을 입증하지는 않는다.

## 원인 분석

### 확인된 사실

- issue가 지정한 별도 CLI 저장소는 생성됐고 두 converter source는 current main과 동일 blob으로 복사됐다.
- 새 저장소에는 독립 Meson project와 tool 선택 option, 설치 target, 사용 문서가 있다.
- core README는 이미 converter 사용자를 새 저장소로 안내한다.
- current main에는 `tools/`, `tools` Meson option, tool-driven loader/saver 활성화, OS별 `-Dtools=all` build가 남아 있다.
- core는 설치 시 `thorvg-1` dependency metadata를 생성하고 새 CLI project는 이를 우선 탐색한다.
- 새 CLI 저장소에는 converter를 build/test하는 GitHub Actions workflow가 현재 없다.
- current SVG regression workflow는 sanitizer, 외부 valid/not-valid corpus, PR-vs-main comparison과 500회 PNG 재현성 검사를 포함한다.
- current Pixel Inspector는 고정 asset과 draw test를 backend별 golden image로 비교한다.
- 열린 legacy 제거 PR은 기존 SVG regression workflow와 설정도 삭제하며, 그 PR의 고정 Pixel Inspector 비교는 backend당 497건에서 차이 0을 보고했다.

### 추론과 판단

- **분리의 근본 동기:** converter는 engine 위의 application이며 release cadence와 dependency 요구가 다르다. 이를 core build option으로 유지하면 engine의 platform CI와 maintenance scope가 application까지 확장된다. 별도 저장소 경계는 타당하다.
- **주요 미완성 지점:** source의 복사는 끝났지만 quality ownership은 아직 완전히 이동하지 않았다. 새 저장소가 자체 CI 없이 core 쪽 source와 workflow부터 삭제하면 converter 변경을 자동 검증하는 주체가 사라진다.
- **regression migration 공백:** old suite와 Pixel Inspector는 겹치는 “render 결과 비교”가 있지만 동일하지 않다. fixed golden test는 알려진 asset의 pixel drift에 강하고, 외부 corpus + sanitizer는 parser robustness와 새 crash input 탐색에 강하다. 하나를 다른 하나로 이름만 바꿔 대체할 수 없다.
- **호환성 위험:** `tools`는 public C++ API는 아니지만 사용자가 실행하는 Meson interface다. 갑작스러운 삭제는 downstream configure를 unknown option으로 실패시킬 수 있다. major/minor release 정책에 맞춘 안내 또는 한 release의 deprecated no-op 전략을 검토할 가치가 있다.
- **feature 계약 위험:** 새 CLI가 설치된 ThorVG를 찾았다는 사실은 SVG/Lottie/GIF 기능이 들어 있다는 뜻이 아니다. configure-time capability probe가 어렵다면 최소한 matrix와 runtime failure message로 잘못된 조합을 명확히 해야 한다.
- **열린 PR 판단:** current legacy 제거 PR은 source cleanup에는 거의 완결된 범위를 보이지만, issue의 “regression tests를 이동”한다는 완료 조건보다 “기존 regression job 삭제”에 가깝다. migration PR 또는 선행 Pixel Inspector/CLI CI 변경이 별도로 필요하다는 판단은 코드와 workflow의 기능 비교에 근거한 추론이다.

## 구현 방향

1. 먼저 새 CLI 저장소에 Linux·Windows·macOS build matrix를 추가한다. 각 job은 ThorVG를 SVG, Lottie, GIF saver가 포함된 조합으로 설치하고 두 executable을 build/install한다.
2. 각 converter에 작은 fixture와 smoke test를 둔다. `svg2png`는 non-empty PNG, 요청 resolution과 반복 실행의 byte/pixel 동일성을, `lottie2gif`는 valid GIF signature, frame 수와 resolution을 확인한다.
3. ThorVG feature가 빠진 dependency 조합도 test한다. configure에서 막을 수 있으면 명확한 Meson error를 내고, runtime에만 알 수 있다면 converter가 지원 누락을 구체적인 exit code/message로 보고하는지 검증한다.
4. core cleanup은 `tools/`, `subdir('tools')`, tool summary와 option, tool이 loader/saver를 암묵적으로 켜는 식, 3개 OS build의 `-Dtools=all`, label/document 참조를 한 commit 계열로 제거한다. `gif` saver 자체는 core API와 saver test가 사용하므로 tool과 함께 무조건 제거하지 않는다.
5. `-Dtools` 제거는 release note와 migration command를 제공한다. 기존 `meson setup ... -Dtools=svg2png` 사용자는 core library를 필요한 loader/saver와 함께 설치한 뒤 별도 CLI project를 build해야 한다.
6. old SVG regression suite의 검증 목적을 표로 나눈다: fixed visual cases, external valid corpus, invalid/crash corpus, PR-vs-main differential, repeated rendering/data race. 각 행의 새 owner와 workflow를 정하기 전에는 기존 job을 삭제하지 않는다.
7. 유지 가치가 높은 최소 SVG는 출처와 기대 결과를 보존해 Pixel Inspector fixture로 옮긴다. pixel-semantic regression은 CPU/GL/WGPU golden으로 검증하되 backend 차이가 의도된 case는 별도 기준을 둔다.
8. 전체 external corpus와 sanitizer crash/leak/timeout 검사는 Pixel Inspector에 무리하게 포함하기보다 core 또는 CLI 저장소의 독립 robustness job으로 유지하는 방안도 비교한다. 실행 시간 때문에 모든 PR에 부적합하면 scheduled/full job과 작은 PR smoke subset으로 나눈다.
9. 500회 PNG 재현성 test는 thread count와 seed를 기록하고 flaky result를 숨기지 않는 반복 test로 이관한다. 단순 golden 1회 비교로 대체하지 않는다.
10. 새 coverage가 default branch에서 실제 성공하고 artifact/report가 확인된 뒤 core의 legacy source와 old workflow를 제거한다. 마지막으로 repository 전체에서 `tools/`, `-Dtools`, old executable build path를 검색한다.

## 초심자 시작 가이드

전체 migration은 초심자에게 권하지 않지만, 범위를 분리한 검증 작업은 기여하기 좋다.

1. current main에서 `-Dtools=svg2png`와 `-Dtools=lottie2gif`를 각각 build해 생성 executable과 자동으로 활성화된 loader/saver를 기록한다.
2. 같은 ThorVG install을 사용해 새 CLI 저장소의 두 tool을 build하고 `--help` 또는 인자 없는 usage, 작은 SVG/Lottie 변환을 실행한다.
3. old와 new executable이 같은 input, resolution, background, FPS에서 만든 output의 크기·pixel·frame 수를 비교한다.
4. SVG loader가 없는 ThorVG와 GIF saver가 없는 ThorVG를 각각 설치해 새 CLI의 실패 단계와 message를 기록한다.
5. old SVG workflow를 “visual diff”, “invalid input robustness”, “repeatability” 세 묶음으로 나누고 Pixel Inspector가 이미 담당하는 항목과 빠진 항목을 체크한다.
6. 빠진 항목 하나만 선택해 새 저장소의 작은 CI job으로 옮긴다. source 삭제와 test migration을 한 PR에서 동시에 시작하지 않으면 실패 원인을 추적하기 쉽다.

## 위험/검증

- 새 CLI 저장소를 GCC/Clang/MSVC와 Linux·Windows·macOS에서 build/install한다.
