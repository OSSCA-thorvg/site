## 이슈 요약

이 issue는 CPU `SwCanvas`의 부분 렌더링 결과가 같은 최종 scene을 새 canvas에 한 번 전체 렌더링한 결과와 달라지는 문제다. 재현은 서로 떨어진 두 content를 사용한다. 왼쪽에는 opacity 128인 정적 Scene 안의 두 사각형이 있고, 오른쪽에는 frame마다 fill 값만 바뀌는 작은 shape가 있다. target은 un-premultiplied `ARGB8888S`다.

첫 frame 이후 실제 dirty 영역은 오른쪽 mover 주변뿐이어야 한다. 그런데 왼쪽 정적 반투명 group의 pixel도 frame마다 더 밝아져 4회 뒤 첫 불일치가 `fresh=0x807727c7`, `partial=0x80ffffff`로 보고된다. 이는 geometry가 잘못 그려졌다기보다 이미 straight-alpha로 내보낸 정적 pixel을 다음 frame에 다시 unpremultiply한 결과와 일치한다.

issue는 닫힌 미병합 PR #4743에서 분리되어 새로 등록됐다. 그 PR은 전체-surface 변환뿐 아니라 dirty rectangle 병합의 capacity 초과와 double-buffer 재사용 문제도 함께 수정하려 했다. 따라서 기존 patch를 그대로 채택하기보다 최소 재현의 직접 원인과 고 fragmentation에서만 나타나는 별도 결함을 독립 test로 나누는 것이 안전하다.

## main 코드 조사

partial rendering은 [Meson에서 기본값 `true`](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/meson_options.txt#L7-L10)다. 사용자가 특별히 끄지 않아도 일반 CPU build가 이 경로를 사용하므로 선택적인 corner case로만 볼 수 없다.

canvas draw 순서는 [`clear` 요청, `preRender()`, scene render, `postRender()`](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/tvgCanvas.h#L104-L118)다. `draw(true)`이면 renderer가 전체 target을 지우고 `fulldraw`가 켜진다. issue의 incremental 경로처럼 `draw()`를 사용하면 이전 frame buffer를 보존하면서 손상 영역만 갱신한다.

SW `preRender()`는 [dirty task를 완료하고 region을 commit한 뒤 그 rectangle만 투명색으로 clear](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/cpu_engine/tvgSwRenderer.cpp#L321-L340)한다. 이후 shape와 image render도 full draw가 아니면 [자신의 bounds와 committed dirty region의 교집합만 다시 raster](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/cpu_engine/tvgSwRenderer.cpp#L399-L492)한다. 따라서 mover와 겹치지 않는 왼쪽 group은 다음 frame에 premultiplied 값으로 다시 그려지지 않는 것이 정상이다.

반면 `postRender()`는 target color space가 `ABGR8888S` 또는 `ARGB8888S`이면 [부분/전체 frame을 구분하지 않고 `rasterUnpremultiply(surface)`를 호출](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/cpu_engine/tvgSwRenderer.cpp#L353-L364)한다. 이 함수는 [surface의 모든 행과 열을 순회](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/cpu_engine/tvgSwRaster.cpp#L1570-L1598)하며 alpha가 0이나 255가 아닌 pixel에 `channel * 255 / alpha`를 다시 적용한다.

unpremultiply는 멱등 연산이 아니다. 예를 들어 alpha 128에서 premultiplied channel 약 60을 straight channel 약 119로 되돌린 뒤, 다음 frame에 119를 다시 입력하면 약 237이 되고 반복 시 255에 포화된다. issue의 정적 group이 흰색으로 drift하는 증상은 이 current-main control flow로 직접 설명된다.

dirty region은 [16개 partition과 partition별 double buffer](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/tvgRender.h#L187-L233)로 관리된다. `commit()`은 input rectangle을 x순으로 정렬한 뒤 contain, 축 방향 merge와 subdivision으로 겹치지 않는 output을 만들려고 한다.

여기에도 별도 위험이 확인된다. [`subdivide()`](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/tvgRender.cpp#L332-L372)는 capacity를 확인하기 전에 참조로 받은 `rhs`의 y 범위를 바꾸고, 공간이 부족하면 log만 남기고 return한다. 호출자는 실패 여부를 받지 못한 채 같은 sweep를 계속한다. 또한 [`commit()`](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/src/renderer/tvgRender.cpp#L375-L449)은 swap된 output을 명시적으로 clear하지 않고 결과를 push한다. 정상적인 `postRender()`가 두 buffer를 clear하지만, merge 자체의 원자성과 재호출 안전성은 함수 내부 계약으로 보장되지 않는다.

현재 SW test는 `ARGB8888S` target에서 mask와 blend의 API 성공을 폭넓게 확인하지만 [마지막 render는 `draw(true)` 전체 redraw](https://github.com/thorvg/thorvg/blob/2b78e1bd7225be4eacb8817b18a493cf567b4f87/test/testSwEngine.cpp#L33-L137)다. 동일 scene의 incremental 결과를 fresh full render와 pixel-by-pixel 비교하는 test는 current main에 없다.

닫힌 [PR #4743](https://github.com/thorvg/thorvg/pull/4743)은 6개 파일에서 region-scoped unpremultiply, restartable merge와 regression test를 제안했고 작성자는 재현 통과와 corpus 검증 결과를 보고했다. 그러나 2026-09-01에 merge 없이 닫힌 뒤 이 issue가 만들어졌으므로 그 설계와 측정값은 참고 증거이지 maintainer가 승인한 해법은 아니다.

## 원인 분석

### 확인된 사실

- public API 재현은 straight-alpha target에서 incremental render와 fresh full render의 pixel 차이를 보고한다.
- current main의 partial pre-render와 paint render는 committed dirty rectangle만 clear하고 다시 그린다.
- current main의 straight-alpha post-render는 dirty 범위와 관계없이 전체 surface를 unpremultiply한다.
- unpremultiply 수식은 alpha가 0과 255 사이인 pixel에 반복 적용할 때 같은 값을 보존하지 않는다.
- current dirty-region subdivision은 capacity 실패 전에 입력 rectangle을 일부 변경하고 실패를 호출자에게 전달하지 않는다.
- current commit은 swap한 output list를 함수 시작 시 명시적으로 비우지 않는다.
- current SW test에는 incremental/fresh pixel 동등성을 고정하는 회귀 test가 없다.
- 기존 구현 PR은 merge되지 않았고 issue로 다시 분리됐다.

### 추론과 판단

- **직접 원인:** 최소 재현의 정적 group drift는 이번 frame에 다시 raster하지 않은 straight-alpha pixel까지 전체-surface unpremultiply가 재처리해서 발생한다. 이는 증상과 코드가 일치하는 강한 결론이다.
- **필요한 불변식:** target buffer는 frame 사이에 straight-alpha 상태로 보존된다. renderer 내부에서 이번 frame에 새로 쓴 영역만 premultiplied 상태이므로, post-render는 그 영역을 정확히 한 번만 변환해야 한다.
- **rectangle 중복 위험:** region-scoped 변환도 committed rectangle이 겹치면 같은 pixel을 두 번 처리해 동일한 drift를 만든다. 그래서 변환 범위 축소와 region merge 정확성은 구현상 연결되지만 각각의 실패를 별도 test로 증명해야 한다.
- **rectangle 유실 위험:** subdivision capacity 실패로 dirty fragment가 사라지면 old pixel이 clear/redraw되지 않아 stale content가 남는다. 이는 issue의 단순 두 rectangle 재현에는 필요하지 않지만 복잡한 scene에서 다른 partial-render 오류를 만들 수 있다.
- **성능 판단:** 부분 frame마다 전체 surface를 순회하지 않으면 큰 정적 scene에서 write bandwidth를 줄일 수 있다. 기존 PR의 성능 수치는 독립 재측정 전에는 확정 사실로 취급하면 안 된다.
- **수정 범위 판단:** `postRender()` 한 줄만 바꾸는 patch는 최소 증상을 고칠 수 있어도, unpremultiply가 신뢰할 region set에 의존하게 되는 순간 merge 실패가 색상 정확성 문제로 확대된다. 회귀 test와 atomic merge 보강을 함께 검토할 이유가 있다.

## 구현 방향

1. issue sample을 unit test 크기로 줄여 같은 scene의 4회 incremental output과 마지막 상태를 한 번 fresh render한 output을 전체 pixel 비교한다. 수정 전 실패하는지 먼저 고정한다.
2. straight-alpha `postRender()`를 full draw/partial-disabled와 partial draw로 분기한다. 전자는 전체 surface, 후자는 committed dirty rectangle만 unpremultiply한다.
3. region overload는 stride를 존중해 rectangle의 각 행만 순회하고 alpha 0/255 fast path를 유지한다. surface 전체의 `premultiplied` bool만으로 부분별 표현 상태를 오판하지 않도록 상태 계약을 문서화한다.
4. committed region이 서로 겹치지 않고 surface bounds 안에 있으며 모든 input union을 덮는지 debug/test helper로 검증한다. 같은 pixel의 중복 변환을 허용하지 않는다.
5. `subdivide()`는 필요한 slot 수를 mutation 전에 계산하고 exact-fit을 허용한다. 부족하면 원본 list를 바꾸지 않은 채 명시적 실패를 반환한다.
6. merge는 scratch list에서 수행하고 capacity 부족 시 grow 후 처음부터 재시도한다. 절반만 변형된 list에서 계속 진행하지 않는다.
7. `commit()`은 output list를 명시적으로 clear한 뒤 결과를 쓰며, 성공한 결과로만 current buffer를 교체한다. 함수 단위로 재호출해도 stale rectangle이 남지 않게 한다.
8. 최소 drift 수정과 large-fragmentation merge 재작성의 commit을 논리적으로 나눈다. test가 어느 결함을 잡는지 명확해지고 review에서 범위를 축소하기 쉽다.

## 초심자 시작 가이드

최종 renderer 수정은 초심자에게 권하지 않지만 재현 test 분리는 좋은 시작점이다.

1. 400×200 buffer 두 개를 만들고 issue의 scene builder를 test helper로 옮긴다.
2. 첫 buffer는 mover fill을 20에서 24까지 바꾸며 `update → draw → sync`하고, 둘째 buffer는 fill 24 scene을 `draw(true)`로 한 번 그린다.
3. 전체 pixel을 비교하고 첫 mismatch 좌표·두 값을 출력하되 test assertion은 차이 수가 0인지 검사한다.
4. target을 `ARGB8888`, `ARGB8888S`, `ABGR8888S`로 바꿔 straight-alpha 두 종류에서만 같은 증상이 나는지 기록한다.
5. 임시로 `postRender()`의 전체 unpremultiply를 막거나 full redraw를 강제해 mismatch가 사라지는지 확인한다. 이는 원인 확인용이지 최종 수정은 아니다.
6. 그 다음 겹치는 작은 rectangle 수를 단계적으로 늘려 dirty merge의 capacity 경계를 별도 test로 만든다.

## 위험/검증

- `ARGB8888S`와 `ABGR8888S`에서 incremental/fresh output이 모든 pixel에서 동일한지 확인한다.
- premultiplied `ARGB8888`·`ABGR8888` 결과가 수정 전후 byte-identical한지 확인한다.
- 정적 반투명 Scene, mask, clip, opacity 1~254, 여러 blend method와 nested offscreen composition을 조합한다.
- dirty 영역과 정적 content가 분리된 경우, 일부 겹치는 경우, 완전히 겹치는 경우를 검사한다.
- old/new bounds, 화면 밖 bounds, 16개 partition 경계와 stride가 width보다 큰 target을 검증한다.
- subdivision이 reserve exact-fit, 1칸 부족, 반복 grow와 매우 많은 fragment에서도 input union을 유실하지 않는지 확인한다.
- committed rectangle끼리 겹치지 않고 각 pixel이 최대 한 번 unpremultiply되는지 instrumentation으로 센다.
- `draw(true)`, `draw(false)`, partial 옵션 비활성 build와 runtime deactivation 경로를 비교한다.
- alpha 0, 1, 127, 128, 254, 255와 channel rounding/포화 값을 고정한다.
- 같은 frame을 수백 회 반복해 drift가 누적되지 않는지 확인한다.
- CPU scalar/SIMD, threads 0/다중 thread, ASan/UBSan/TSan과 전체 unit test를 실행한다.
- 최적화 build에서 full-surface와 작은 dirty-region frame의 처리 시간과 memory write를 비교하되 성능 때문에 정확성 검사를 완화하지 않는다.
