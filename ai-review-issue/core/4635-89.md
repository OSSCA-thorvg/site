## 이슈 요약

비디오를 기존 `Picture`/`Canvas`와 transform API로 다루면서 재생·일시정지·정지·탐색·반복·볼륨·음소거를 제공하는 실험적 media 기능이다. 플랫폼별 native decoder를 plugin 형태로 연결하고, decode는 비동기로 진행하며, CPU와 GPU renderer 모두에서 가능한 한 native resource를 활용해 복사를 줄이는 것이 목표다.

2026-07-31 현재 공통 명세/API와 Apple 항목은 완료로 표시되어 있다. Linux, Android, Windows, Web 구현 PR은 열려 있고 GPU 최적화 항목은 미완료다. 따라서 이 이슈는 단일 버그 수정이 아니라 여러 backend의 설계·통합·검증을 추적하는 상위 기능 이슈다.

## main 코드 조사

현재 공통 [`MediaLoader`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/tvgMediaLoader.h#L28-L49)는 `ImageLoader`를 상속하고 현재/전체 시간, 볼륨, pause/mute/loop 상태를 보유한다. `play()`, `pause()`, `stop()`, `seek()`, `loop()`, `volume()`, `mute()`는 플랫폼 backend가 구현해야 하는 순수 virtual 함수다.

[`Video`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/tvgVideo.cpp#L31-L145)는 내부 `Picture`를 소유하고, 해당 Picture에서 media loader를 가져와 제어 호출을 위임한다. 탐색 시간과 볼륨의 범위 검사는 공통 계층에서 수행한다. 이 구조 덕분에 비디오 frame은 기존 Picture의 크기·transform·Canvas 합성 경로를 재사용할 수 있다.

build에서 media는 [실험적 loader option](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/meson_options.txt#L12-L16)이며 기본 loader 집합에는 포함되지 않는다. [`src/loaders/media/meson.build`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/meson.build#L1-L23)는 Darwin/iOS에서만 Apple 하위 디렉터리를 선택하고, 그 밖의 시스템에서는 backend를 찾지 못했다는 로그와 함께 `nullptr`을 반환하는 [fallback factory](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/tvgMediaLoader.cpp#L23-L29)를 컴파일한다. 즉 현재 main에서 실제 재생 backend가 있는 플랫폼은 Apple 계열뿐이다.

loader 선택은 [`LoaderMgr`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/renderer/tvgLoaderMgr.cpp#L121-L155)에서 확장자 `mp4` 또는 mime `mp4`만 media로 분류한다. 다른 container/codec 조합은 TODO로 남아 있으므로 각 native backend가 지원하는 입력과 공통 API가 받아들이는 입력의 계약을 먼저 고정해야 한다.

Apple backend는 AVFoundation의 decoded `CVPixelBuffer`를 BGRA로 요청한다. [`_push()`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/apple/tvgAvfMediaLoader.mm#L121-L154)는 각 row를 ThorVG 소유 ring buffer로 복사하고, [`sync()`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/apple/tvgAvfMediaLoader.mm#L459-L476)는 선택된 ring frame을 다시 `surface.data`로 복사한다. 현재 구현은 안전한 CPU surface 경로를 우선한 것으로 보이며, 이슈가 목표로 한 native resource/minimal-copy GPU 경로는 아직 별도 최적화 과제다.

재생 queue는 [`_buildQueue()`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/apple/tvgAvfMediaLoader.mm#L232-L250)에서 만들고, decode frame은 track frame rate 기반 dispatch timer가 [`_tick()`](https://github.com/thorvg/thorvg/blob/f38fc532fc36be7700508d6cc60a4f4c392fbecc/src/loaders/media/apple/tvgAvfMediaLoader.mm#L264-L314)으로 poll한다. destructor는 queue에서 동기적으로 close한 뒤 ring/surface memory를 해제한다. 이 backend는 다른 플랫폼에서도 명시해야 할 핵심 계약이 “callback 중단 → native object 정리 → ThorVG buffer 해제” 순서임을 보여준다.

열린 플랫폼 PR은 각각 [Linux/GStreamer #4552](https://github.com/thorvg/thorvg/pull/4552), [Android #4531](https://github.com/thorvg/thorvg/pull/4531), [Windows #4595](https://github.com/thorvg/thorvg/pull/4595), [Web #4503](https://github.com/thorvg/thorvg/pull/4503)이다. Linux와 Windows PR은 draft 상태다. Linux 리뷰에는 GStreamer object ref 해제, 비동기 state change 이후 callback teardown, preroll/첫 frame 경쟁 조건이 지적되어 있어 공통 수명·상태 테스트의 필요성을 뒷받침한다.

현재 `test/`에는 `Video` 또는 media 전용 테스트가 없다. API가 main에 들어왔더라도 상태 전이와 입력 범위, unsupported backend, platform frame 출력에 대한 자동 회귀 보호는 아직 부족하다.

## 원인 분석

### 확인된 사실

- 공통 `Video`/`MediaLoader` API와 C binding, Apple backend는 현재 main에 있다.
- non-Apple build는 media option을 켜도 fallback factory가 `nullptr`을 반환한다.
- main의 loader 선택은 현재 `mp4` 확장자/mime만 media로 분류한다.
- Apple CPU 경로는 decoded pixel buffer에서 ring buffer로, ring buffer에서 render surface로 두 번 복사한다.
- Linux·Android·Windows·Web 구현은 별도 열린 PR이며 GPU 최적화는 이슈 TODO로 남아 있다.
- main 테스트에는 media/Video 전용 회귀 테스트가 없다.

### 추론과 판단

- 가장 큰 난점은 decode API 호출 자체보다 플랫폼마다 다른 callback thread, EOS/seek semantics와 native buffer 소유권을 하나의 `MediaLoader` 상태 계약으로 맞추는 일이다.
- `paused`, `curTime`, `frameUpdated` 같은 공통 상태를 backend마다 임의 시점에 갱신하면 같은 API 호출이 플랫폼별로 다른 결과를 낼 수 있다.
- zero-copy는 “복사 제거” 한 줄 변경이 아니다. decoded buffer의 pixel format, stride, lifetime/fence와 각 renderer가 import할 수 있는 native resource를 함께 협상해야 한다.
- 오디오 재생과 video frame 표시가 별도 clock을 쓰면 seek·pause·loop에서 drift 또는 첫 frame 누락이 생길 수 있으므로 media clock의 기준을 backend 계약에 포함해야 한다.
- 플랫폼 PR을 병렬로 merge한 뒤 문제를 찾기보다 공통 conformance test와 teardown invariant를 먼저 고정하는 편이 통합 위험을 낮춘다.

## 구현 방향

1. `MediaLoader`의 상태 전이 표를 문서와 테스트로 고정한다.
   - load 직후, play, pause, resume, seek, stop, EOS, loop, close
   - 각 호출의 동기/비동기 완료 시점과 `curTime`/`paused`/첫 frame 의미
2. 공통 contract test harness를 만든다. 실제 decoder 없이 deterministic fake backend로 API 범위, 중복 호출, 실패와 teardown 순서를 검증한다.
3. 플랫폼 plugin은 한 PR씩 다음 최소 범위로 통합한다.
   - CPU frame 출력과 정확한 수명
   - audio/volume/mute와 clock 동기화
   - seek/loop/EOS 및 오류 복구
   - GPU native resource import/복사 감소
4. callback에는 loader raw pointer만 장기간 캡처하지 않는다. 취소 token 또는 generation을 두고 close가 신규 callback을 막은 뒤 진행 중 작업을 drain하도록 한다.
5. frame hand-off 계약에 format, dimensions, stride, timestamp, ownership, release/fence를 명시한다. renderer가 import할 수 없으면 안전한 CPU copy로 fallback한다.
6. input 지원은 container 확장자와 codec 능력을 분리한다. backend capability query 또는 명시적 failure를 제공하고, `mp4` 문자열만으로 실제 decode 가능성을 보장하지 않는다.
7. GPU 경로는 platform-native buffer별 작은 prototype과 benchmark로 검증한다. unsupported color space/stride에는 기존 CPU surface 경로를 유지한다.

## 초심자 시작 가이드

전체 backend 구현은 초심자에게 권하지 않는다. 다음 하위 작업은 비교적 안전하다.

1. fake `MediaLoader`로 `Video`의 잘못된 seek/volume 범위와 loader 부재 시 반환값을 검사한다.
2. load → play → pause → seek → play → stop → close의 기대 상태 표를 작성한다.
3. media option을 끈 build와 non-Apple fallback build에서 명시적으로 실패하는 회귀 테스트를 만든다.
4. Apple test asset 하나에 대해 첫 frame, 중간 seek frame, EOS frame의 timestamp와 pixel checksum을 기록한다.

native decoder callback이나 GPU resource ownership을 수정하는 작업은 platform maintainer와 함께 진행한다.

## 위험/검증

- 같은 상태 함수를 연속 호출하고 play 중 seek/stop/close를 경쟁시켜 deadlock, UAF와 callback-after-close를 검사한다.
- 0초, duration, 범위 밖 seek와 EOS 직전/직후 seek를 검증한다.
- loop on/off, pause/resume, muted/volume 경계에서 audio와 video clock 차이를 장시간 측정한다.
- preroll이 느리거나 첫 decoded frame이 늦는 입력에서도 빈 surface, 오래된 frame과 첫 frame 누락을 검사한다.
- variable frame rate, 회전 metadata, odd stride, alpha/color space, 4K 이상과 손상된/빈 파일을 포함한다.
- native buffer import 실패, renderer 전환과 device loss에서 CPU fallback과 자원 해제가 동작하는지 확인한다.
- sanitizer/ThreadSanitizer, platform leak tool과 callback generation logging으로 teardown 경로를 확인한다.
- CPU copy byte/frame, upload 횟수, decode-to-present latency, dropped frame, memory high-water mark를 backend별로 기록한다.
- 최소 지원 OS/device 및 codec matrix를 CI와 실제 장치 검증으로 나눈다.
