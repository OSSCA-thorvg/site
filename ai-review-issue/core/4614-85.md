## 이슈 요약

CID-keyed CFF 폰트는 `draw()`/`sync()`에서 멈추고, CFF2 variable 폰트는 access violation을 일으킨다는 제보다. 현재 구현은 CFF1의 단일 Private DICT 모델을 전제로 하면서 `CFF2` table도 거의 같은 순서로 읽는다. 하지만 CID/CFF2에서는 glyph가 사용할 Font DICT와 Private DICT를 FDSelect로 골라야 하고, CFF2의 header·Top DICT·INDEX 구조도 CFF1과 다르다.

이 작업은 “Noto CJK 한 파일을 통과”시키는 데서 끝나면 안 된다. 지원하지 않는 구조를 만났을 때도 parser가 입력 범위를 벗어나거나 같은 byte에서 무한 반복하지 않고 명확히 실패하는 것이 첫 완료 조건이다.

## main 코드 조사

[`OtfReader` 상태](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.h#L30-L67)는 CFF table 시작, 하나의 CharStrings INDEX, global subroutine INDEX, **하나의** local subroutine INDEX만 보관한다. glyph마다 다른 Font DICT/Private DICT를 선택할 FDArray·FDSelect 상태는 없다.

현재 [`CFF()`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.cpp#L155-L203)는 먼저 `CFF `를 찾고 없으면 `CFF2`를 찾는다. 그러나 그 뒤에는 두 포맷 모두에 다음 CFF1 순서를 적용한다.

- header 크기 뒤 데이터를 `skip()`해 Name INDEX로 취급한다.
- 다음 데이터를 `uint16` count가 있는 Top DICT INDEX로 해석한다.
- CFF1일 때만 String INDEX를 한 번 더 건너뛴다.
- Top DICT에서 operator 17과 top-level operator 18만 읽어 CharStrings와 한 Private DICT를 찾는다.

공식 [OpenType CFF2 사양](https://learn.microsoft.com/en-us/typography/opentype/spec/cff2#organization-of-the-cff2-table)은 CFF2가 5-byte header, 길이가 header에 기록된 raw TopDICT, 그 직후의 GlobalSubrINDEX 순서라고 정의한다. CFF1 Name INDEX와 Top DICT INDEX를 건너뛰는 현재 방식과 다르다. CFF2 INDEX의 count도 `uint32`인데, 현재 [`skip()`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.cpp#L38-L54)와 subroutine 해석은 `u16` count를 사용한다.

Top DICT의 escaped operator는 [`DICT()`에서 byte 12를 만나면 두 byte를 건너뛰는 방식](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.cpp#L81-L117)으로 모두 무시된다. 따라서 CFF2의 필수 FontDICTINDEXOffset(12, 36), 선택적 FontDICTSelectOffset(12, 37), CFF1 CID의 FDArray/FDSelect를 수집하지 않는다. 공식 사양은 [각 glyph가 FontDICTSelect를 통해 PrivateDICT를 선택](https://learn.microsoft.com/en-us/typography/opentype/spec/cff2#fontdictindex-fontdictselect-and-fontdict)할 수 있고 local subroutine은 해당 PrivateDICT 범위에서만 사용할 수 있다고 설명한다.

CharString interpreter에도 별도 진행 위험이 있다. [`charStrings()`의 switch](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.cpp#L338-L465)는 일부 path와 subroutine operator만 처리한다. 나머지는 `operand(values, b, p); continue;`로 보낸다. [`operand()`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgOtfReader.cpp#L313-L336)는 숫자 encoding일 때만 `p`를 증가시킨다. 지원하지 않는 operator byte가 default로 가면 `p`가 그대로여서 같은 byte를 계속 읽을 수 있다. CFF2의 `vsindex`·`blend`와 hint 관련 operator도 현재 switch에서 구현되지 않았다.

하위 reader의 [`u8`, `u16`, `u32`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/sfnt/tvgSfntReader.h#L82-L113)는 직접 포인터를 역참조한다. 상위 parser가 offset, INDEX header, offset array와 object 끝을 읽기 전에 `validate()`하지 않으면 access violation을 막을 수 없다. 현재 CFF 경로는 header 첫 4 byte만 검사한 뒤 많은 offset 산술과 읽기를 수행한다.

현재 저장소의 font 테스트/fixture에는 `FDArray`, `FDSelect`, `CFF2` 회귀를 명시한 사례가 없다. 제보된 Noto 폰트는 재현 자료로 유용하지만, 저장소 테스트에는 라이선스와 용량을 확인한 최소 fixture가 필요하다.

## 원인 분석

### 확인된 사실

- CFF reader는 global `subrs` 하나만 보관하며 glyph별 Font DICT 선택 구조가 없다.
- escaped DICT operator 12를 통째로 건너뛰므로 FDArray와 FDSelect offset을 읽지 않는다.
- CFF2를 찾은 뒤에도 CFF1의 Name INDEX와 Top DICT INDEX 순서를 적용한다.
- CFF2의 공식 header/TopDICT/GlobalSubrINDEX 순서와 INDEX count 크기는 현재 parser의 가정과 다르다.
- 지원하지 않는 CharString operator가 default 경로에 들어가면 cursor가 전진하지 않을 수 있다.
- 원시 정수 reader는 자체 bounds 검사를 하지 않으며 CFF parser의 구조별 validation이 제한적이다.

### 추론과 판단

- CFF1 CID hang은 잘못 선택된 local subroutine뿐 아니라 미지원 operator에서 cursor가 정지하는 경로로도 설명될 수 있다. 실제 멈춘 byte와 call stack을 기록해야 둘을 구분할 수 있다.
- CFF2 access violation은 CFF2 table을 CFF1 INDEX로 해석해 잘못된 offset을 만드는 구조적 불일치가 가장 강한 후보지만, sanitizer stack trace로 확정해야 한다.
- FDSelect만 추가하고 CFF2 layout을 그대로 두는 수정은 한 증상을 다른 범위 밖 읽기로 옮길 수 있다.
- 완전한 variable CFF2 blend 계산이 당장 어렵다면, 지원 여부를 header 단계에서 판정해 안전하게 `false`를 반환하는 것이 crash/hang보다 우선이다.

## 구현 방향

1. byte cursor/span abstraction을 만들어 모든 다중 byte 읽기와 offset 덧셈 전에 남은 길이를 검사한다. overflow가 나거나 object 범위를 벗어나면 즉시 실패한다.
2. CFF1과 CFF2 header/table 탐색을 별도 함수로 분리한다.
   - CFF1: Header → Name INDEX → Top DICT INDEX → String INDEX → Global Subr INDEX
   - CFF2: Header의 `topDICTSize` → raw TopDICT → GlobalSubrINDEX
3. CFF1/CFF2의 INDEX count 크기와 offset array 규칙을 포맷별로 구현하고 첫 offset, 단조 증가, 마지막 object 끝을 검증한다.
4. Top/Font/Private DICT operator를 context별로 해석한다. FDArray/FontDICTINDEX와 FDSelect/FontDICTSelect, 각 Private DICT의 LocalSubrINDEX를 모델에 보존한다.
5. glyph id로 FDSelect를 조회한 뒤 해당 Font DICT의 Private DICT와 local subroutine을 CharString 실행기에 전달한다.
6. CharString loop에 “매 반복마다 cursor가 전진하거나 명시적으로 stack frame을 전환해야 한다”는 invariant를 둔다. 알 수 없는 operator, 부족한 operand, stack overflow/underflow는 실패 처리한다.
7. CFF2의 `vsindex`와 `blend`를 정확히 지원하거나, variation data가 필요한 font를 명시적으로 거부한다. byte를 무시한 채 path를 계속 만들지 않는다.
8. 파싱 실패를 `Text::load()` 또는 glyph 변환 실패로 전파해 render worker가 hang하지 않도록 한다.

## 초심자 시작 가이드

전체 구현은 초심자에게 권하지 않는다. 하위 작업으로는 안전성 테스트를 먼저 분리할 수 있다.

1. 제보 폰트를 `fonttools ttLib` 등으로 조사해 CFF/CFF2, FDArray 수, FDSelect format, glyph별 FD index를 기록한다.
2. ASan/UBSan과 timeout을 켠 최소 렌더 테스트로 CFF1 hang의 마지막 cursor byte, CFF2 crash의 최초 범위 밖 읽기를 수집한다.
3. 작은 byte 배열로 “미지원 operator에서도 함수가 제한 시간 안에 false를 반환”하는 단위 테스트를 만든다.
4. INDEX count/offset이 잘린 입력과 역순 offset 입력을 추가해 새 bounded reader부터 검증한다.

실제 decoder 변경은 OpenType 사양의 table diagram과 코드의 cursor 단위를 나란히 놓고 진행해야 한다. 제보 폰트 하나에서 화면이 나오는 것만으로 포맷 지원이 완료됐다고 판단하지 않는다.

## 위험/검증

- 제보된 CID-keyed CFF 폰트가 timeout 없이 성공하거나 안전하게 실패하는지 확인한다.
- 제보된 CFF2 variable 폰트가 ASan/UBSan 오류 없이 성공하거나 안전하게 실패하는지 확인한다.
- 기존 non-CID CFF1 폰트의 glyph outline, advance, baseline이 변하지 않는지 pixel/metric 비교를 한다.
- FDSelect가 서로 다른 Private DICT를 고르는 두 glyph를 렌더해 local subroutine이 섞이지 않는지 검사한다.
- CFF2의 단일 FontDICT와 다중 FontDICT, variation 있음/없음 경로를 분리해 검사한다.
- 모든 INDEX에서 잘린 header, 잘못된 `offsetSize`, 감소하는 offset, object 끝 초과를 거부하는지 확인한다.
- CharString operand stack, subroutine 깊이 10, return 위치, instruction/cursor 진행 한계를 검사한다.
- 미지원/잘못된 operator가 무한 반복하지 않고 deterministic한 실패를 반환하는지 timeout test를 둔다.
- font load와 실제 `draw(true)`/`sync()`까지 포함한 회귀 테스트를 여러 차례 실행한다.
- font corpus fuzzing에 CFF1 CID와 CFF2 seed를 추가하고 crash·hang을 모두 실패로 수집한다.
