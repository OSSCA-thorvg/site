## 이슈 요약

재현은 source shape에 target shape를 alpha mask로 연결하고 source를 Scene에 넣은 뒤 `scene->remove()`로 모두 제거한다. 호출자는 source와 target의 초기 reference를 계속 보유하므로 두 객체는 살아 있다. 그 다음 target을 다른 Scene에 직접 추가하려 하지만 current main에서는 target의 `parent`가 이전 Scene을 계속 가리켜 `Result::InsufficientCondition`이 된다.

문제는 단순 재사용 실패에 그치지 않는다. 이전 Scene이 파괴된 뒤 target의 bounds/transform 계산이 raw `parent` chain을 따라가면 해제된 Scene을 읽을 수 있다. 따라서 이슈의 showstopper 분류처럼 object lifecycle과 memory safety를 함께 다뤄야 한다.

## main 코드 조사

[`SceneImpl::insert()`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/src/renderer/tvgScene.h#L332-L363)은 실제 child인 `target`만 `ref()`하고 `paints`에 넣는다. 그 뒤 child의 `parent`뿐 아니라 child가 보유한 `clipper`와 `maskData->target`의 `parent`도 같은 Scene으로 설정한다. borrowed clipper/mask target은 Scene의 `paints` list에 추가되거나 Scene이 직접 ref하지 않는다.

같은 파일의 [`clearPaints()`와 `remove()`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/src/renderer/tvgScene.h#L300-L330)는 list의 child에만 `unref()`를 호출한다. `remove()`의 guard도 `PAINT(paint)->parent == this`만 검사하고 list membership을 확인하지 않은 채 `unref()`와 `paints.remove()`를 수행한다. 두 함수 모두 살아남은 child의 clipper/mask target parent를 명시적으로 지우지 않는다.

[`Paint::Impl::unref()`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/src/renderer/tvgPaint.h#L103-L125)는 그 호출을 받은 paint 자신의 `parent`를 null로 바꾼다. ref count가 0이면 destructor가 clipper와 mask target을 unref하지만, 재현처럼 caller reference가 남아 source가 살아 있으면 destructor는 실행되지 않는다. 따라서 source의 `unref()`만으로 borrowed target의 parent가 정리되지 않는다.

[`Paint::Impl::mask()`와 `clip()`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/src/renderer/tvgPaint.h#L171-L218)은 새 target/clipper에 이미 parent가 있으면 `InsufficientCondition`을 반환한다. stale parent 때문에 다른 Scene의 `add()`가 실패하는 현상은 이 소유권 guard의 의도된 결과이고, guard를 약화하는 것은 해결책이 아니다.

[`Paint::Impl::ptransform()`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/src/renderer/tvgPaint.h#L155-L169)은 `while (p->parent)`로 raw chain을 순회하고 parent transform을 누적한다. old Scene이 해제된 뒤 stale pointer가 남으면 이 함수가 dangling object를 `PAINT()`로 변환해 접근할 수 있다.

current test에는 [`Scene Clear And Reuse Shape`](https://github.com/thorvg/thorvg/blob/03aabc1157b208ca3d3b2358686560026afce9fc/test/testScene.cpp#L98-L126)가 있지만 list에 직접 들어간 shape만 제거·재사용한다. borrowed mask target을 살아 있는 source와 함께 재사용하는 경우는 없다. 이슈가 참조한 [닫힌 PR #4791](https://github.com/thorvg/thorvg/pull/4791)은 `detachBorrowed()`와 membership scan, mask target 회귀 test를 제안했으나 2026-09-10 현재 closed/unmerged이며 분석한 main에는 변경이 없다.

## 원인 분석

### 확인된 사실

- Scene insert는 실제 child와 그 clipper/mask target 모두에 raw `parent=this`를 기록한다.
- Scene은 실제 child만 ref하고 `paints` list에 보관한다.
- remove/clear는 list child만 unref하며 borrowed paint의 parent를 직접 지우지 않는다.
- source에 caller reference가 남으면 source destructor가 실행되지 않아 mask target도 함께 정리되지 않는다.
- mask/clip/add는 parent가 남은 paint의 재소유를 거부하며 `ptransform()`은 parent chain을 역참조한다.
- 기존 reuse test는 plain child만 다루고, 참조 PR은 닫혔으며 current main에 병합되지 않았다.

### 추론과 판단

- **근본 원인:** `parent`는 Scene의 직접 소유 child와 ref하지 않는 borrowed clipper/mask target에 동시에 사용되지만, Scene 해제 경로는 직접 child의 `unref()`가 모든 parent를 정리한다고 가정한다. source가 살아남으면 이 가정이 깨진다.
- **재사용 실패와 UAF는 같은 invariant 위반의 두 결과다.** old Scene이 아직 살아 있으면 add guard가 target을 거부하고, Scene이 먼저 파괴되면 transform/bounds가 dangling parent를 읽을 수 있다.
- **`unref()`를 mask target에 추가하는 방식은 틀리다.** Scene은 borrowed target의 ref를 직접 취득하지 않았으므로 extra unref는 source가 가진 참조 또는 caller의 참조를 잘못 감소시킬 수 있다. 필요한 것은 Scene이 기록한 raw parent link의 조건부 detach다.
- **단순 무조건 detach도 위험하다.** 두 unparented source가 같은 clipper/target을 공유한 뒤 함께 한 Scene에 들어갈 수 있고, borrowed paint 자체가 Scene child로 들어가는 구성도 가능하다. 한 source를 제거할 때 다른 관계가 남아 있다면 parent를 지우면 안 된다.
- **`parent == this`는 membership 증거가 아니다.** borrowed paint도 같은 값을 갖기 때문에 `Scene::remove(borrowed)`가 실제 list 원소가 아닌 객체를 unref하지 않도록 별도 membership 확인이 필요하다.

## 구현 방향

1. Scene이 child를 제거하기 전에 그 child의 clipper와 mask target을 수집한다. Scene이 이 raw parent를 설정한 경우에만 detach 후보로 둔다.
2. `clearPaints()`는 전체 list가 비워지므로 각 child의 borrowed link를 unref 전에 정리할 수 있다. 단, 같은 borrowed paint가 list의 실제 child인 경우에도 최종 list 제거 순서와 상관없이 parent가 올바르게 null이 되는지 test한다.
3. `remove(paint)`는 먼저 `paints`에서 정확한 iterator를 찾아 membership을 증명한다. 찾지 못하면 parent 값과 무관하게 `InsufficientCondition`을 반환하고 ref count를 건드리지 않는다.
4. 한 child만 제거할 때는 나머지 list를 훑어 borrowed candidate가 다른 child의 clipper/mask target이거나 실제 child인지 확인한다. 어떤 관계든 남으면 parent를 유지하고, 아무 관계도 없을 때만 `parent == this`를 null로 만든다.
5. detach는 ref/unref를 하지 않고 raw parent만 정리한다. damage와 기존 child `unref()` 순서는 현재 renderer contract를 유지한다.
6. helper 이름과 주석에서 owning child와 borrowed link를 명시하고, 장기적으로는 하나의 `parent` 필드가 두 의미를 겸하는 구조를 별도 owner/scene-context로 분리할지 검토한다.

참조 PR의 single-pass 아이디어와 test는 유용한 출발점이지만, 먼저 행렬 형태의 ownership test를 만들고 각 case에서 parent와 ref count를 예상값으로 고정한 뒤 패치를 평가해야 한다.

## 초심자 시작 가이드

1. 이슈의 최소 test를 `testScene.cpp`에 임시로 넣고 `other->add(target)`이 `InsufficientCondition`으로 실패하는지 확인한다.
2. `source->mask(target)` 전후, `scene->add(source)` 후, `scene->remove()` 후의 source/target parent와 ref count를 debugger로 기록한다.
3. `SceneImpl::insert()`에서 target parent가 Scene으로 설정되는 반면 paints list에는 source만 있는 것을 확인한다.
4. source 초기 reference를 제거해 source가 Scene과 함께 파괴되는 경우에는 왜 문제가 숨는지 destructor/unref 순서를 비교한다.
5. 먼저 remove membership test를 추가하고, borrowed target에 `scene->remove(target)`을 호출해 ref count가 변하지 않아야 함을 고정한다.
6. shared target과 actual-child 조합 test를 만든 뒤 조건부 detach helper를 구현한다. sanitizer 실행 전에는 해제된 Scene의 pointer를 직접 출력하거나 역참조하지 않는다.

## 위험/검증

- 이슈의 mask target 재사용 test가 수정 전 실패, 수정 후 성공하며 source/target의 최종 unref가 정확히 0인지 확인한다.
- clipper에 대해 같은 remove/clear/reuse test를 대칭으로 추가한다.
- `scene->remove(source)`, `scene->remove()` 전체 clear, Scene destructor 세 경로를 모두 검사한다.
- caller reference가 없는 source와 있는 source를 나눠 destructor가 즉시 실행되는 경우도 검증한다.
- 두 source가 같은 mask target 또는 clipper를 공유할 때 첫 제거 후 parent가 유지되고 마지막 제거 후에만 null이 되는지 확인한다.
- borrowed target이 Scene의 실제 child이기도 한 경우 한 관계 제거가 child ownership을 풀지 않는지 확인한다.
- 다른 Scene이 소유한 paint와 `parent != this`인 paint를 remove했을 때 ref count와 list가 변하지 않아야 한다.
- 같은 paint의 중복 insert가 거부되고 iterator/membership scan이 list를 손상하지 않는지 확인한다.
- remove 직후 target의 bounds/transform, 다른 Scene add, mask/clip 재사용을 수행한다.
- nested Scene, source가 Scene인 경우, clipper 자체가 mask를 가진 경우의 parent chain을 검사한다.
- partial rendering과 damage가 켜진 상태에서 detach 순서가 freed render data에 접근하지 않는지 확인한다.
- 전체 unit test를 ASan/UBSan/LeakSanitizer로 실행해 UAF, double free, leak과 ref underflow가 없는지 확인한다.
