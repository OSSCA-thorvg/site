## 이슈 요약

제보자는 animation 중 사각형 artifact가 보이며 공식 web example에서도 재현된다고 보고했다. 약 3.7초짜리 첨부 영상에서는 회로 모양 animation이 움직이는 동안 정상 geometry 밖으로 짧은 검은 직사각형이 나타났다 사라진다. 계속 남는 parsing 오류보다 특정 frame의 render data, clip 범위 또는 GL 상태가 잘못 재사용되는 유형에 가깝다.

첨부 JSON은 1900×600, 24fps, 72 frame이며 같은 precomposition을 정상 scale과 `[-100, -100, 100]` scale로 두 번 배치한다. 내부에는 세 단계의 nested precomp, alpha matte 4개, mask 100개가 있다. mask mode는 `f` 57개와 `n` 43개이고, current parser에서 `f`는 `Difference`, `n`은 `None`으로 해석된다. mask path 자체는 static이지만 5개 transform property가 animated다. 즉 “복잡한 path가 매 frame 바뀌는 문제”보다 움직이는 중첩 composition의 bounds·clip·mask 상태가 좌우 instance 사이에서 잘못 공유되거나 갱신되는지 먼저 볼 가치가 높다.

이 issue가 등록되기 직전 current main에는 clipper를 갱신할 때 기존 clip array 대신 빈 array를 넘기는 변경이 들어왔다. 이 시간적 근접성은 강한 bisect 후보지만, 해당 차이만으로 원인이라고 확정할 수는 없다. 이틀 전 animation frame 변경의 invalidation을 `All`에서 `Children`으로 줄인 최적화와, 그보다 앞선 GL state-cache 최적화도 한 frame성 artifact의 후보로 남는다.

## main 코드 조사

Lottie builder는 [`build()`에서 root scene에 composition 크기의 사각형 clip을 항상 추가](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/loaders/lottie/tvgLottieBuilder.cpp#L1759-L1773)한다. 첨부 asset은 precomp가 중첩되므로 각 단계의 viewport clip도 중첩된다. 최상위에는 같은 precomp를 정상 방향과 양축 음수 scale로 복제한 두 layer가 있어 clip transform과 bounds가 서로 대칭인 두 instance가 동시에 그려진다.

[`updateMasks()`](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/loaders/lottie/tvgLottieBuilder.cpp#L1352-L1409)는 precomp 또는 matte가 있으면 intermediate Scene을 만들고 첫 mask를 scene의 mask/clip으로 연결한다. 이후 mask mode가 바뀌면 `pShape->mask(shape, method)`로 composition chain을 만든다. 첨부 asset의 57개 Difference mask와 alpha matte가 이 경로를 반복 사용하므로 intermediate render target과 mask bounds가 계속 교차한다.

current [`Paint::Impl::update()`의 clipping 단계](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/tvgPaint.cpp#L243-L264)는 fast-track이 아니면 `noClip`이라는 빈 array로 clipper를 갱신한 뒤 그 render data만 현재 `clips`에 추가한다. [직전 변경](https://github.com/thorvg/thorvg/commit/3035329f1cd2a05174f0ed67316478346931b039)은 이 호출에 기존 `clips`를 전달하던 동작을 빈 array 전달로 바꿨다. 이는 “clip shape 자체에는 바깥 clip을 중복 적용하지 않는다”는 의도로 볼 수 있지만, 중첩 clip의 renderer data가 바깥 clip context를 필요로 했는지는 backend별 확인이 필요하다.

GL shape 준비는 [`RenderUpdateFlag::Clip`이 있을 때 전달받은 clip render data를 `sdata->clips`에 복사](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/gpu_engine/gl/tvgGlRenderer.cpp#L1327-L1379)한다. shape render는 [clip array가 비어 있지 않으면 `drawClip()`을 먼저 호출](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/gpu_engine/gl/tvgGlRenderer.cpp#L1222-L1237)한다. 따라서 clip array 내용이나 `Clip` dirty flag가 한 frame 늦으면 GL command sequence가 바로 달라질 수 있다.

[`drawClip()`](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/gpu_engine/gl/tvgGlRenderer.cpp#L510-L555)은 clip을 batch 경계로 보고 stencil-cover batch를 비운다. 각 clip geometry의 bounds를 target paint의 `viewBounds`와 교차한 scissor로 그리고, target bounds 전체를 덮는 사각형 mask task를 만든다. 코드 주석도 full pass viewport를 쓰면 이웃 animation에 영향을 줄 수 있다고 명시한다. 첨부 asset처럼 좌우 반전 instance가 같은 viewport에 있는 경우 이 경계 계산은 증상과 직접 맞닿아 있다.

실제 [`GlClipTask::run()`](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/gpu_engine/gl/tvgGlRenderTask.cpp#L334-L360)은 color write를 끄고 front/back stencil을 증가·감소시킨 다음, 사각형 mask task로 stencil/depth를 정리한다. 잘못된 scissor, stale bounds, color mask나 stencil op 복구 누락이 있으면 path가 아니라 사각형 cover geometry의 흔적이 노출될 수 있다.

animation frame 변경은 [`Animation::frame()`](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/tvgAnimation.cpp#L38-L49)에서 loader가 frame을 바꾸면 Picture에 `RenderUpdateFlag::Children`만 표시한다. 이 동작은 [최근 최적화 commit](https://github.com/thorvg/thorvg/commit/4a089b8b3bc576c147846b7efc4f174fea7e15a6)에서 이전 `All` invalidation을 대체했다. vector Picture는 [그 flag를 내부 vector paint에 전달](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/tvgPicture.h#L57-L90)하고 Scene은 [모든 child update에 같은 flag를 전파](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/tvgScene.h#L86-L105)한다. 각 animated property가 필요한 구체 flag를 빠짐없이 mark하지 않으면 기존 GL geometry·bounds·clip array가 남을 수 있다.

GL은 [최근 큰 state-cache 최적화](https://github.com/thorvg/thorvg/commit/bc71d1076bf571e4b9c5dcd7e3d70eecd9defd62)를 거쳤다. current [`GlStateCache::invalidate()`](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/src/renderer/gpu_engine/gl/tvgGlStateCache.cpp#L100-L136)는 CPU 쪽 가정만 무효화하고 GL state를 reset하지 않는다고 명시한다. frame 사이 또는 외부 WebGL code와 context를 공유할 때 cache와 실제 color mask, stencil/scissor 상태가 어긋나는지도 독립적으로 확인해야 한다.

현재 GL engine test는 [여러 mask method와 shape를 draw/sync](https://github.com/thorvg/thorvg/blob/bd6d2e74788a5da5f1bf477c7efdcc7173038c1c/test/testGlEngine.cpp#L33-L137)하지만 결과 pixel을 검사하지 않고, 한 canvas에서 nested precomp를 frame별로 갱신하는 시나리오도 없다. 순간적인 사각형 artifact는 API 성공만 검사하는 test를 그대로 통과할 수 있다.

## 원인 분석

### 확인된 사실

- issue에는 GL animation 중 나타나는 사각형 artifact의 영상과 재현 JSON이 제공됐다.
- 첨부 JSON은 같은 precomp의 정상·양축 반전 instance, 세 단계 nested precomp, alpha matte 4개와 mask 100개를 포함한다.
- mask 중 57개는 Difference이고 43개는 None이며, mask path는 static이고 일부 transform은 animated다.
- Lottie root scene은 composition 크기의 사각형 clip을 갖고 nested precomp는 clip을 중첩한다.
- GL clip은 stencil path와 target bounds 크기의 사각형 mask task를 사용하며 scissor를 clip/paint bounds에서 계산한다.
- animation frame invalidation은 최근 `All`에서 `Children`으로 축소됐다.
- issue 등록 약 9분 전 main에 clipper update의 입력 clip array를 비우는 변경이 반영됐다.
- current GL test는 draw/sync 성공은 확인하지만 frame별 pixel이나 artifact 부재를 검증하지 않는다.

### 추론과 판단

- **1순위 진단:** issue 직전 clip-context 변경의 부모/자식 commit을 같은 asset과 고정 frame으로 비교한다. 시간적 근접성과 nested precomp clip 구조 때문에 가장 저렴한 bisect 지점이지만, 코드 읽기만으로 인과관계는 확정되지 않았다.
- **2순위 진단:** `Children` 최적화 전후를 비교한다. 최적화 이전에서 사라지면 animated transform이 바꾼 clip geometry, composition bounds 또는 mask target에 구체 dirty flag가 누락된 것이다. 최종 수정은 무조건 `All`로 되돌리기보다 누락된 mark를 좁혀야 한다.
- **3순위 진단:** 두 후보 모두 재현되면 GL state-cache 변경 전후와 actual GL state를 확인한다. cover 사각형과 유사한 흔적은 stale scissor/stencil/color-mask 상태로도 설명할 수 있다.
- **instance 간 누출 가설:** 정상 scale instance와 음수 scale instance가 같은 precomp data를 참조한다. pooling된 Paint/RenderData가 instance별 transform·clip context를 분리하지 못하거나 첫 instance의 bounds가 다음 instance에 남으면 한쪽의 사각형 cover가 다른 쪽에 노출될 수 있다.
- **Difference mask 가설:** Difference chain은 intermediate FBO와 mask composition을 많이 만든다. 그러나 mask path가 static이므로 parser 자체보다 animated parent transform에 따른 FBO bbox와 compose/scissor 갱신 누락이 더 유력하다.
- **단순 shader 문제 가능성은 낮음:** artifact가 지속적인 색 오류가 아니라 특정 frame의 축 정렬 사각형이라면 fragment color 계산보다 command/state/bounds 수명 문제와 더 잘 맞는다. 실행 추적 전에는 이 역시 추론이다.

## 구현 방향

1. 첨부 영상을 frame 단위로 분해해 첫 불량 frame과 앞뒤 정상 frame 번호를 고정한다. JSON의 24fps frame과 화면 녹화 frame을 구분하고, `Animation::frame(n)`으로 해당 source frame을 직접 재생한다.
2. current main, clip-context 변경의 parent, `Children` 최적화의 parent를 같은 GL/GLES 환경에서 실행해 3점 bisect를 먼저 끝낸다. full history bisect보다 빠르게 원인 계층을 구분할 수 있다.
3. asset을 단계적으로 축소한다. 먼저 root의 반전 instance 하나를 제거하고, nested precomp를 한 단계씩 평탄화하며, Difference mask group을 절반씩 제거한다. artifact를 유지하는 최소 조합을 만든다.
4. update 단계에서 frame별로 각 clip RenderData의 pointer, update flags, transform, geometry bounds, viewport와 clip count를 기록한다. 정상 전후 frame에서 stale 값이 처음 생기는 지점을 찾고 임시 로그는 최종 PR에서 제거한다.
5. render 단계에서는 `drawClip()`의 `viewBounds`, `clipBounds`, scissor, draw depth와 GlClipTask 전후의 color mask·stencil func/op를 캡처한다. RenderDoc 또는 WebGL command capture로 사각형이 어느 task에서 쓰였는지 확인한다.
6. clip-context 변경이 원인이면 모든 backend에서 clipper가 받아야 할 context의 계약을 먼저 정의한다. 단순 revert가 CPU/WGPU의 이중 clip이나 recursive clip 문제를 되살리지 않는지 nested clip 최소 test로 검증한다.
7. dirty flag 누락이 원인이면 animated property가 바뀐 Paint와 clip/mask/compositor bounds에 필요한 최소 flag를 mark한다. `All` 복귀는 진단용 대조군으로만 사용하고 성능 최적화의 목적을 유지한다.
8. GL state-cache가 원인이면 실제 state를 cache가 정확히 소유하도록 전환 경계를 수정하고, 외부 context 사용 전후 invalidate 계약을 test한다. 매 draw마다 무조건 전체 state를 reset하는 수정은 성능 회귀를 만들 수 있다.
9. 축소 asset 또는 public API scene을 GL regression test에 추가한다. 불량 frame의 artifact 영역은 투명/배경색이어야 하고 실제 content 영역은 비어 있지 않다는 pixel invariant를 readback으로 검사한다.

첫 수정 PR은 재현 test와 확정된 한 계층의 수정에 집중하는 편이 좋다. clip semantics, animation invalidation, GL state cache를 한꺼번에 바꾸면 회귀 원인과 성능 영향을 다시 분리하기 어렵다.

## 초심자 시작 가이드

최종 수정은 초심자에게 권하지 않지만 원인 축소와 test fixture 작성은 기여하기 좋다.

1. 첨부 JSON을 frame 0부터 71까지 한 frame씩 렌더하고 PNG로 저장한다. artifact가 처음 나타나는 frame과 바로 앞뒤 frame을 기록한다.
2. 최상위 두 layer 중 음수 scale layer를 삭제한 사본과 정상 scale layer를 삭제한 사본을 만든다. 어느 쪽 또는 두 instance가 함께 있을 때만 재현되는지 비교한다.
3. `comp_0`, `comp_1`, `comp_2`, `comp_3`을 한 단계씩 제거하거나 inline하여 최소 nested clip 깊이를 찾는다.
4. Difference mask 57개를 절반씩 제거하는 방식으로 artifact를 유지하는 최소 mask set을 찾는다. 매 단계에서 JSON이 여전히 72 frame으로 재생되는지 확인한다.
5. 문제가 되는 frame의 content 바깥 작은 사각 영역을 pixel readback해 non-background pixel 수를 센다. 정상 frame은 0, 불량 frame은 0보다 큰 invariant로 test를 시작한다.
6. 원인 commit 전후 결과가 갈리는 최소 asset과 frame 번호를 maintainer에게 먼저 공유한다. 이 자료만으로도 renderer 수정의 탐색 비용을 크게 줄일 수 있다.

## 위험/검증

- 첨부 원본을 frame 0~71 순차 재생, 임의 seek, 역방향 seek, loop 경계에서 각각 반복한다.
- 정상 scale 단독, 음수 scale 단독, 두 instance 동시 배치를 비교한다.
- nested precomp 깊이 1~3과 composition 밖으로 이동·회전·확대되는 clip을 검사한다.
- Difference, Add, Subtract, Intersect mask와 alpha matte를 단독·연쇄 조합으로 검사한다.
- clip fast-track이 가능한 축 정렬 사각형과 회전/clip 중첩으로 fast-track이 불가능한 경우를 모두 검사한다.
- GL clip의 scissor와 stencil cover가 target paint bounds 밖 pixel을 바꾸지 않는지 readback한다.
- frame마다 `All`을 강제한 대조군과 최적화된 flag 경로가 pixel-identical한지 비교한다.
- desktop GL, GLES, WebGL과 적어도 두 GPU vendor에서 반복 실행해 state-cache와 driver 의존성을 확인한다.
- CPU와 WGPU 결과를 semantic 기준으로 비교해 loader 공통 오류와 GL 전용 오류를 분리한다.
- 한 canvas에 animation 하나, 동일 animation 두 개, 서로 다른 animation 여러 개를 두고 instance 간 상태 누출을 검사한다.
- 외부 application이 scissor, stencil, color mask, framebuffer state를 바꾼 뒤 renderer를 호출하는 공유-context 시나리오를 검사한다.
- GL engine pixel regression과 전체 loader/renderer test를 실행하고 frame time, command 수, intermediate FBO 할당량을 비교한다.
