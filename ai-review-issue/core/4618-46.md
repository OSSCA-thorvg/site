## 이슈 요약

`-Wpadded`가 보고하는 구조체 내부/꼬리 padding을 정리해 불필요한 메모리 낭비를 줄이자는 작업이다. 이슈 본문은 여러 renderer와 loader, 공개 header에서 나온 경고를 제시하고 파일 또는 디렉터리별로 나누어 진행할 것을 제안한다.

중요한 점은 padding 경고가 곧 버그나 낭비를 뜻하지 않는다는 것이다. 자연 alignment, 상속/virtual dispatch, 공개 ABI, GPU uniform 계약을 위한 padding은 유지해야 할 수 있다. 따라서 안전한 내부 table부터 크기 전후를 측정하고, 위험한 구조는 별도 설계 검토로 분리해야 한다.

2026-07-29 현재 [PR #4620](https://github.com/thorvg/thorvg/pull/4620)이 열려 있으며 `tvgSvgLoader.cpp`의 translation-unit 내부 lookup table 21개에서 pointer/function pointer를 작은 enum·int보다 앞에 배치하는 첫 하위 작업을 제시한다. 아직 `main`에는 반영되지 않았다.

## main 코드 조사

이슈가 언급한 실제 GCC 진단 이름은 `-Wpadding`이 아니라 `-Wpadded`다. 현재 저장소에서 이 flag를 기본 빌드에 추가한 코드는 없고, 번들된 [`catch.hpp`는 오히려 해당 진단을 억제](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/test/catch.hpp#L30-L48)한다. 따라서 재현 가능한 inventory를 만들려면 어떤 compiler/version/target과 flags를 사용했는지 함께 기록해야 한다.

[`PictureOps`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/renderer/tvgLoader.h#L42-L55)는 1-byte에 가까운 base의 `Type caller` 뒤에 pointer 두 개와 `bool`을 둔다. 상속 시작 offset과 pointer alignment 때문에 진단이 발생할 수 있다. 같은 파일의 [`FontMetrics`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/renderer/tvgLoader.h#L191-L205)는 여러 `Point`, `float`, enum 뒤에 `void* engine`이 있어 pointer 정렬을 위한 내부 padding 후보가 된다.

렌더 공통 구조에는 성격이 다른 사례가 섞여 있다.

- [`RenderTrimPath`와 `RenderStroke::Dash`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/renderer/tvgRender.h#L332-L362)는 float/pointer/작은 enum·bool 조합이다.
- [`RenderShape`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/renderer/tvgRender.h#L394-L406)는 owning pointer와 destructor를 가지므로 단순 크기뿐 아니라 copy/ownership 사용도 확인해야 한다.
- [`RenderEffect` 파생 타입](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/renderer/tvgRender.h#L472-L519)은 virtual base와 작은 byte field, float가 섞여 있어 base tail padding 재사용과 파생 layout이 compiler ABI에 따라 달라질 수 있다.

공개 [`Paint` class의 private 구현 pointer`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/inc/thorvg.h#L49-L64)와 이를 상속하는 [`Picture`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/inc/thorvg.h#L1600-L1611)에서도 경고가 보고됐다. 공개 class의 크기·alignment·상속 layout은 라이브러리 ABI와 연결되므로 내부 table과 같은 기준으로 재배치하면 안 된다.

반면 [`tvgSvgLoader.cpp`의 `boxTags`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/svg/tvgSvgLoader.cpp#L55-L65), [`styleTags`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/svg/tvgSvgLoader.cpp#L1112-L1145), [`graphicsTags`/`groupTags`](https://github.com/thorvg/thorvg/blob/df31fd1b59a00ffb0811837c9753d9cb5766ac6d/src/loaders/svg/tvgSvgLoader.cpp#L2215-L2247)는 파일 내부 `static constexpr` 배열이다. 외부 ABI에 노출되지 않고 접근도 named field로 하지만 positional aggregate initializer를 사용하므로, member 순서를 바꿀 때 initializer 순서도 반드시 함께 바꿔야 한다.

열린 [PR #4620의 patch](https://github.com/thorvg/thorvg/pull/4620/files)는 이러한 내부 table에서 pointer/`size_t`/function pointer를 앞에 두고 `int`/enum을 뒤로 옮기며 initializer와 관련 macro도 동기화한다. 공개 `SvgLoader`는 ABI 위험 때문에 범위에서 제외했다.

## 원인 분석

### 확인된 사실

- 현재 main에는 `-Wpadded`를 기본 활성화하는 build option이 없고, Catch header에는 억제 pragma가 있다.
- 경고 대상은 translation-unit 내부 lookup table부터 공개 class와 polymorphic renderer 구조까지 성격이 다양하다.
- `tvgSvgLoader.cpp`의 여러 내부 table은 큰 pointer 계열 field 사이에 작은 `int`/enum field가 있어 inter-member padding이 생길 수 있다.
- 내부 table은 positional initializer를 사용하므로 member만 재배치하면 값이 잘못 연결되거나 compile error가 난다.
- 열린 PR #4620은 내부 SVG lookup table 일부만 다루며 아직 main에 반영되지 않았다.

### 추론과 판단

- 전체 경고 수를 목표로 잡으면 의도적이거나 제거 불가능한 tail padding까지 억지로 바꾸기 쉽다. 절감 byte × 동시 instance 수로 우선순위를 정하는 편이 낫다.
- `static constexpr` lookup table은 instance 수가 배열 원소 수만큼 고정되어 있어 절감량을 정확히 계산할 수 있고 ABI 위험도 낮아 좋은 첫 범위다.
- public/polymorphic type은 member 순서 변경으로 경고가 줄더라도 ABI, RTTI/vtable 관련 layout 또는 derived size가 바뀔 수 있다.
- `packed` attribute나 pragma로 경고만 숨기면 비정렬 접근과 플랫폼 성능/안전성 문제가 생길 수 있으므로 해결책이 아니다.

## 구현 방향

1. GCC/Clang, target architecture, compile flags를 고정해 전체 `-Wpadded` inventory를 생성한다. 진단마다 파일·type·원인·현재 `sizeof`/`alignof`를 기록한다.
2. 경고를 다음 위험 등급으로 나눈다.
   - 파일 내부 POD/lookup table
   - 내부 runtime object
   - public/상속/virtual type
   - GPU buffer·직렬화·FFI 등 외부 layout 계약
3. 첫 PR은 하나의 파일 또는 작은 table 군만 다룬다. 큰 alignment field를 먼저 배치하고 모든 positional initializer/macro를 함께 갱신한다.
4. 변경 전후 `sizeof(element) × 배열 원소 수`를 기록하고 실제 padding warning 감소를 compiler output으로 증명한다.
5. 내부 runtime object는 생성 수, cache locality, ownership/copy code를 조사한 뒤 별도 PR로 진행한다.
6. public/virtual/external-layout type은 ABI dump와 지원 정책을 먼저 확인한다. 이득이 작거나 layout이 계약이면 경고 예외와 근거 주석을 선택한다.
7. 진단 정책 자체는 관련 [Issue #4601](https://github.com/thorvg/thorvg/issues/4601)의 build-time detection 논의와 연결하되, cleanup PR에는 관련 없는 build 변경을 섞지 않는다.

## 초심자 시작 가이드

`tvgSvgLoader.cpp`의 작은 `static constexpr` table 하나를 골라 다음 순서로 진행한다.

1. 현재 compiler에서 `sizeof(table[0])`, `alignof(decltype(table[0]))`와 `-Wpadded` 메시지를 기록한다.
2. 8-byte pointer/`size_t`, 4-byte `int`, 작은 enum 순으로 alignment를 적는다.
3. member 순서를 바꾸고 배열 initializer 및 생성 macro의 인자 순서를 같은 commit에서 수정한다.
4. table lookup test와 SVG 전체 test를 실행해 tag, size, handler가 이전과 같은 값인지 확인한다.
5. 변경 전후 element 크기와 전체 배열 byte 수를 PR 설명에 남긴다.

공개 header, virtual class, shader와 공유하는 구조체는 첫 하위 작업으로 고르지 않는다. compiler 경고가 사라졌다는 사실만으로 `#pragma pack`이나 `packed`를 추가하지 않는다.

## 위험/검증

- 동일 compiler/version/target에서 대상 경고가 실제로 사라지고 새 경고가 생기지 않는지 확인한다.
- 32-bit와 64-bit에서 `sizeof`/`alignof` 전후를 기록하고 한 플랫폼에서 크기가 오히려 커지지 않는지 확인한다.
- positional aggregate initializer와 macro expansion의 field 순서가 모두 새 선언과 일치하는지 검사한다.
- SVG tag·style·gradient lookup이 기존과 같은 handler와 enum을 반환하는지 전체 parser test를 실행한다.
- runtime object는 constructor, copy/move, destructor와 direct aggregate initialization 사용처를 검색한다.
- 공개/virtual type은 ABI checker와 지원 대상 compiler에서 class layout 변화를 확인한다.
- `memcpy`, hashing, serialization, IPC/FFI, GPU upload에 type의 byte representation을 쓰는지 검색한다.
- 단순 warning 감소뿐 아니라 실제 전체 byte 절감량과 대표 workload의 memory 차이를 기록한다.
- GCC와 Clang에서 진단을 비교하고, MSVC를 다룬다면 C4820 등 별도 진단 의미를 분리한다.
