## 이슈 요약

Lottie `guitar.json`을 GIF로 저장하면 노란 캔 몸체의 작은 밝은 영역이 원본처럼 연한 노란색으로 유지되지 않고 회색·베이지색에 가까운 patch로 보인다. 이슈에는 잘못 인코딩된 결과와 기대 결과가 함께 첨부되어 있으며, maintainer는 다른 Lottie resource도 함께 확인해 달라고 요청했다. 후속 댓글에는 `train.json`, `traveling.json`에서 transparent 배경과 white 배경의 결과가 다르다는 추가 사례도 있다.

이번 이슈는 직전 GIF palette 수정이 merge되기 약 6분 전에 열렸고, 해당 수정의 review에서도 이 이슈를 별도의 확인 대상으로 직접 언급했다. 분석 기준 `main`에는 그 수정이 이미 포함되어 있지만 이슈는 계속 Open 상태이고 merge 뒤에도 배경별 사례가 추가됐다. 따라서 이미 해결된 이전 결함의 중복이라기보다, 수정 뒤 남은 색상 양자화·투명도 품질 문제로 보는 것이 타당하다.

`guitar.json`의 shape paint를 정적으로 세면 선언된 solid fill/stroke RGBA는 15종이고 gradient shape는 없다. 그러나 opacity layer, antialias edge와 alpha composition은 최종 500×500 raster frame에서 훨씬 많은 중간 RGB를 만든다. GIF frame에서 transparency index 하나를 제외하면 표현 가능한 가시 색상은 최대 255개이므로, 선언 색상 수가 적다는 사실만으로 최종 raster가 palette에 손실 없이 들어간다고 볼 수 없다.

## main 코드 조사

현재 encoder는 [`TRANSPARENT_IDX=0`, alpha threshold 127, bit depth 8](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L52-L55)을 고정한다. [`_getClosestPaletteColor()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L81-L125)는 transparency entry를 제외하고 k-d tree를 탐색하며 `|ΔR| + |ΔG| + |ΔB|`가 가장 작은 palette entry를 고른다. 사람의 색상 인지나 작은 highlight의 의미를 별도로 가중하지 않는 RGB Manhattan distance다.

[`_splitPalette()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L166-L266)는 pixel 집합에서 RGB 범위가 가장 넓은 축을 골라 histogram median으로 분할한다. 마지막 cell에는 포함된 모든 pixel의 RGB 평균을 palette 색으로 기록한다. 동일 RGB만 남은 cell은 해당 색을 range 전체에 채우고 leaf로 표시한다. 직전 수정으로 고정 pixel 수 분할보다 rare color를 잃기 어려워졌지만, 최종 cell 수와 평균 대표색이라는 근본 제약은 남아 있다.

[`_pickChangedPixels()`와 `_makePalette()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L268-L318)는 alpha가 127 이상인 pixel만 모아 frame별 8-bit local palette를 만든다. 첫 frame은 모든 visible pixel, transparent 모드는 매 frame의 모든 visible pixel, background 모드는 이전 frame과 RGB가 달라진 pixel이 대상이다. palette index 0을 transparency에 예약하므로 `_splitPalette()`가 실제 가시 색에 쓰는 범위는 1–255다.

[`_thresholdImage()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L321-L372)는 주석 그대로 dithering 없이 각 visible pixel을 하나의 nearest palette color로 치환한다. transparent 모드에서는 alpha 127 미만을 완전 투명으로 만들고 나머지를 palette에 넣는다. background 모드에서는 이전 frame과 RGB가 같은 pixel을 transparent index로 표시하고 달라진 pixel만 양자화한다. 반투명 edge를 연속 alpha로 보존하는 경로는 없다.

encoder는 [`256-entry local color table`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L415-L473)을 매 frame 기록하고 graphics control extension의 transparent color index를 0으로 설정한다. GIF89a 규격도 local color table을 최대 256 entry로 제한하고 투명도를 단일 color index로 표현한다. 따라서 단순히 table 크기를 늘리는 구현 방향은 규격상 불가능하다.

[`gifWriteFrame()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifEncoder.cpp#L608-L619)은 매 frame `_makePalette()`, `_thresholdImage()`, LZW write를 고정 순서로 호출한다. dithering이나 다른 quantizer를 선택하는 인자는 없다. 반면 기반 encoder의 current implementation은 [`GifMakePalette()`에 dither용 build mode](https://github.com/charlietangora/gif-h/blob/70b645280d5e687f5217177c9cfa2889b0a2ad5f/gif.h#L379-L404)를 전달하고 [`GifDitherImage()`](https://github.com/charlietangora/gif-h/blob/70b645280d5e687f5217177c9cfa2889b0a2ad5f/gif.h#L406-L513)에서 Floyd–Steinberg error diffusion을 수행할 수 있다. [`GifWriteFrame()`](https://github.com/charlietangora/gif-h/blob/70b645280d5e687f5217177c9cfa2889b0a2ad5f/gif.h#L823-L845)은 dither flag로 threshold와 dither를 선택한다. 다만 이 upstream 경로는 ThorVG가 추가한 alpha threshold와 transparent-frame 처리 계약을 알지 못하므로 그대로 복사할 수는 없다.

[`GifSaver::run()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifSaver.cpp#L34-L83)은 straight-alpha `ABGR8888S` buffer에 animation을 render하고, background paint가 있으면 `transparent=false`, 없으면 `true`로 모든 frame을 encoder에 전달한다. 이 분기가 후속 댓글의 transparent/white 차이를 조사해야 하는 직접적인 코드 근거다. [`GifSaver::save()`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/src/savers/gif/tvgGifSaver.cpp#L117-L154)의 `quality`는 현재 `TVG_UNUSED`라 사용자가 화질·속도 전략을 선택할 수도 없다.

현재 [`GIF saver test`](https://github.com/thorvg/thorvg/blob/ff1b9909d424663168272f0a15b9c7ae6322c308/test/testSavers.cpp#L31-L59)는 작은 Lottie를 white background로 저장한 뒤 API 성공만 확인한다. 생성 GIF를 decode해 RGB, alpha, palette, frame disposal 또는 색차를 검사하지 않으므로 이번과 같은 시각적 회귀를 탐지하지 못한다.

## 원인 분석

### 확인된 사실

- 분석 기준 `main`은 직전 palette 생성 수정이 merge된 commit이며, 그 review에서 이번 이슈가 별도 확인 대상으로 언급됐다. 이슈는 merge 후에도 Open이다.
- current encoder는 frame마다 8-bit local palette를 만들고 index 0을 transparency에 예약해 가시 색에 255 entry를 사용한다.
- palette cell의 대표색은 포함된 pixel의 RGB 평균이며, pixel은 RGB Manhattan distance가 가장 가까운 단일 entry로 치환된다.
- current frame 변환은 명시적으로 dithering을 사용하지 않는다.
- alpha는 127을 기준으로 binary transparency가 되며, background 유무에 따라 palette 대상과 unchanged-pixel 처리가 달라진다.
- public `quality` 인자는 GIF saver에서 사용되지 않는다.
- 기존 test는 encode 성공만 검사하고 decoded 화질은 검증하지 않는다.
- 재현 asset에는 gradient shape나 animated paint color가 없지만 opacity와 antialiasing으로 최종 raster의 중간 색상이 생길 수 있다.

### 추론과 판단

- **가장 가능성 높은 원인:** 작은 연노랑 highlight가 차지하는 pixel 수가 적고 주변의 antialias·opacity 합성 색이 많은 frame에서, modified median split이 그 색을 독립 entry로 보존하지 못하거나 평균색으로 이동시킨 뒤 nearest-color 검색이 회색·베이지 entry를 선택했을 가능성이 높다.
- **아직 확정되지 않은 부분:** 문제 frame의 source RGBA, 생성 GIF의 local palette 256개, 해당 pixel이 선택한 index와 `|ΔR|+|ΔG|+|ΔB|`를 함께 dump하지 않았으므로 위 설명을 확정된 root cause로 단정할 수 없다. 수정 전에 이 네 값을 먼저 고정해야 한다.
- **두 현상의 분리:** 불투명 노란 면 내부의 highlight 손실은 palette quantization 문제로 우선 조사해야 한다. 댓글의 transparent/white 차이는 alpha 127 threshold, matte color, frame delta와 disposal이 함께 개입할 수 있는 별도 축이다. 하나의 원인으로 섣불리 합치면 안 된다.
- **규격 제약:** palette entry를 256보다 늘리는 방식은 해결책이 아니다. rare but chromatically distinct color를 보존하는 quantizer, perceptual distance, dithering 또는 이들의 quality별 조합이 필요하다.
- **dithering 후보:** upstream Floyd–Steinberg 경로는 시작점이 될 수 있지만 transparent pixel을 가로질러 error를 확산하지 않는 규칙, frame 경계에서 error state를 공유하지 않는 규칙, delta pixel의 transparency 처리와의 결합을 ThorVG에 맞게 설계해야 한다.
- **품질 trade-off:** spatial dithering은 평균 색차를 낮출 수 있지만 작은 면에 speckle을 만들고 LZW 압축률을 낮추며 animation에서 temporal flicker를 만들 수 있다. 그래서 눈으로 한 frame만 비교하는 검증으로는 부족하다.

## 구현 방향

1. `guitar.json`을 이슈와 같은 크기·fps·background 조건으로 render해 잘못 보이는 정확한 frame 번호와 pixel 좌표를 찾는다. GIF 저장 직전 `ABGR8888S` frame과 저장 후 decoded RGBA를 함께 보존한다.
2. palette dump 도구로 해당 frame의 256개 local color entry, source RGB, 선택된 index·RGB와 색차를 출력한다. highlight 색이 palette에 없는지, 있는데 검색이 잘못된 entry를 고르는지 먼저 구분한다.
3. 작은 synthetic image test를 추가한다. 큰 yellow 영역, small pale-yellow patch, antialias-like intermediate colors를 넣어 current threshold 경로에서 patch 색차가 커지는 상황을 재현하고 decoded GIF pixel을 수치로 검증한다.
4. 최소 두 후보를 같은 corpus에서 비교한다. 첫째, rare color의 pixel 수뿐 아니라 RGB separation을 반영하는 palette split 또는 representative 선택. 둘째, transparency-aware Floyd–Steinberg dithering. CIEDE2000 또는 선형 RGB 오차와 edge-weighted metric을 함께 기록한다.
5. `quality`를 전략 선택에 연결한다면 낮은 quality는 빠른 threshold, 높은 quality는 개선 quantizer/dither처럼 API 의미를 문서화한다. quality 값에 따라 결과가 조용히 불안정해지지 않도록 deterministic output test를 둔다.
6. transparent 모드에서는 alpha 127 미만 pixel로 error를 전달하거나 그 RGB를 palette 통계에 섞지 않는다. opaque background 모드에서는 이전 frame과 같은 pixel을 transparent index로 내보내는 delta 최적화 및 disposal 결과를 유지한다.
7. 먼저 source frame 전체를 올바르게 palettize하는 correctness test를 통과시킨 뒤, changed-pixel palette 최적화와 LZW 용량을 다시 계측한다. 최적화 때문에 rare color가 frame마다 다른 entry로 흔들리는지도 확인한다.

첫 PR은 정확한 pixel/palette regression과 한 가지 최소 quantization 개선으로 제한하는 편이 좋다. quality API의 정책 변경이나 전면적인 perceptual quantizer 도입은 corpus 결과와 성능 자료를 바탕으로 후속 작업으로 분리할 수 있다.

## 초심자 시작 가이드

1. `guitar.json`을 PNG frame sequence와 GIF로 각각 저장하고 ImageMagick 또는 giflib로 GIF를 frame별 RGBA로 decode한다. 눈으로 보이는 frame과 pixel 좌표를 먼저 고정한다.
2. encoder의 `_writePalette()` 직전에 1–255 entry를 출력하고 source pixel과 가장 가까운 entry를 함께 기록한다. 기존 palette dump 예제를 참고하되 임시 로그는 최종 PR에서 제거한다.
3. source RGB와 decoded RGB에 대해 단순 RGB 오차와 perceptual 색차를 계산한다. 전체 평균뿐 아니라 이슈가 가리킨 작은 영역의 최대·평균 오차를 별도로 본다.
4. 32×32 synthetic buffer에서 배경색 두세 개와 2×2 rare highlight를 만든 뒤 중간 antialias 색을 추가한다. asset 전체보다 작은 test로 palette split 결과를 이해한다.
5. upstream `GifDitherImage()`를 읽고 error가 오른쪽·다음 행 pixel로 7/16, 3/16, 5/16, 1/16 전달되는 흐름을 확인한다. 바로 복사하지 말고 alpha 0과 frame delta에서 어떤 pixel을 건너뛸지 먼저 test로 적는다.
6. transparent와 white background를 각각 저장해 disposal 후 합성 결과가 같은 기준 image와 일치하는지 확인한다. 색상 양자화와 투명도 문제를 서로 다른 assertion으로 둔다.

처음부터 Lottie 전체 corpus를 반복하기보다 하나의 문제 frame과 synthetic image에서 palette 부재·검색 오류·alpha 문제를 구분한 뒤 범위를 넓히면 원인과 개선 효과를 훨씬 쉽게 설명할 수 있다.

## 위험/검증

- 이슈의 `guitar.json`을 동일 조건으로 저장하고 표시된 highlight 영역의 decoded RGB·색차가 개선되는지 확인한다.
- source frame, local palette와 decoded frame을 artifact로 남겨 어떤 entry가 선택됐는지 재현 가능하게 만든다.
- maintainer가 요청한 Lottie resource corpus를 transparent·white background 두 조건으로 encode해 평균·상위 1%·최대 색차를 비교한다.
- `train.json`, `traveling.json` 사례에서 transparent index, disposal method와 composited output을 frame별로 검사한다.
- alpha 126, 127, 128의 경계와 semi-transparent antialias edge가 의도한 결과를 내는지 확인한다.
- 완전 불투명 frame, 완전 투명 frame, changed pixel이 없는 frame, 모든 pixel이 바뀐 frame과 단일 색 frame을 test한다.
- small rare color, high-frequency texture, smooth gradient, 256색 이하 exact palette와 256색 초과 image를 각각 검증한다.
- dithering을 사용한다면 transparent pixel 및 frame 밖으로 error가 새지 않고, 동일 입력의 결과가 deterministic한지 확인한다.
- animation을 재생해 frame별 palette 변화가 temporal flicker를 늘리지 않는지 확인한다.
- output GIF의 file size, encode wall time, peak memory와 LZW 압축률을 기존 결과와 비교한다.
- GIF를 여러 decoder와 browser에서 열어 local color table, transparency와 disposal 호환성을 확인한다.
