## 이슈 요약

이 이슈는 platform-native video resource를 renderer surface에 가능한 한 적은 복사로 전달하고, sync 시점에는 double/triple buffer의 pointer를 교체하는 방식을 제안한다. alpha channel이 없는 native format에는 alpha 무시와 premultiplication 정책도 명시한다.

체크리스트에는 Android 항목이 완료로 표시되어 있지만 분석 기준 main에는 Android media backend가 없다. 따라서 체크리스트를 현재 main 구현 상태로 간주하면 안 된다. 이 리뷰는 현재 main에서 확인되는 Apple·Web 경로를 기준으로 원인을 분석하고, 아직 main에 없는 platform 구현은 별도 선행 작업으로 구분한다.

## main 코드 조사

[`media/meson.build`](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/meson.build#L1-L22)는 Apple에서 AVFoundation backend, Emscripten에서 Web backend를 선택하고 나머지 system에서는 fallback loader를 빌드한다. 현재 main tree에는 Android·Windows·Linux 전용 media backend가 없으므로 해당 platform 최적화를 같은 변경으로 바로 적용할 대상이 아직 없다.

공통 [`MediaLoader`](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/tvgMediaLoader.h#L25-L51)는 재생 상태와 제어 API를 정의하지만 native frame을 게시·반납하는 공통 buffer 소유권 API는 제공하지 않는다. 실제 surface 수명과 동기화는 각 backend 구현에 남아 있다.

Apple header는 [`BUFFER_COUNT = 3`인 frame 배열과 write/latest index, mutex, frameUpdated flag](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/apple/tvgAvfMediaLoader.h#L31-L72)를 보유한다. decoder callback의 [`_push()`](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/apple/tvgAvfMediaLoader.mm#L111-L151)는 `CVPixelBuffer`를 lock한 뒤 row stride를 비교해 loader 소유 frame slot으로 `memcpy`한다. 첫 번째 copy는 native decoder memory를 ThorVG가 관리하는 ring으로 옮긴다.

그 뒤 [`sync()`](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/apple/tvgAvfMediaLoader.mm#L403-L423)는 새 frame이 있을 때 최신 ring slot 전체를 다시 `surface.data`로 `memcpy`한다. 즉 새 frame마다 native buffer→ring slot, ring slot→render surface의 두 복사가 발생한다. `read()`는 surface를 straight ARGB로 설정하고 `premultiplied = false`, `alphaIgnored = true`로 표시한다.

Apple loader의 [정리 경로](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/apple/tvgAvfMediaLoader.mm#L311-L331)는 세 frame과 `surface.data`를 각각 해제한다. 단순히 `surface.data = frames[latest]`만 대입하면 기존의 별도 소유 관계가 사라지므로 double-free, 해제 누락 또는 decoder의 동시 덮어쓰기를 만들 수 있다.

Web backend는 [`typed_memory_view(...).set(data)`](https://github.com/thorvg/thorvg/blob/d8342de1aae57284b56ad4241efa8f9dd7d43fd4/src/loaders/media/web/tvgWebMediaLoader.cpp#L43-L81)로 browser frame을 WASM surface로 복사한다. browser resource와 WASM heap 사이에는 Apple과 다른 메모리 경계가 있으므로 pointer swap을 그대로 공통 적용할 수 없다.

Android video playback 제안 [PR #4531](https://github.com/thorvg/thorvg/pull/4531)과 Windows 실험 구현 [PR #4595](https://github.com/thorvg/thorvg/pull/4595)는 platform 방향을 이해하는 참고 자료지만, 분석 기준 main에는 포함되지 않았다. 특히 이슈 체크 상태가 branch/PR의 진행을 반영했을 가능성은 추론일 뿐 현재 main의 확인된 사실이 아니다.

## 원인 분석

### 확인된 사실

- Apple decoder callback은 native pixel buffer를 3-slot loader buffer 중 하나로 복사한다.
- `sync()`는 최신 loader buffer를 별도의 `surface.data`로 다시 복사한다.
- mutex는 latest index와 update flag 게시를 보호하지만 renderer가 특정 slot을 언제까지 읽는지를 표현하는 상태는 없다.
- 입력 stride가 width×4와 다를 때 `_push()`는 row별로 유효 pixel만 복사해 packed slot을 만든다.
- Apple surface는 straight ARGB, non-premultiplied, alpha ignored로 표시된다.
- 현재 main의 platform 선택에는 Android·Windows·Linux native media backend가 없다.
- Web backend에는 browser memory와 WASM heap 사이의 명시적 copy가 있다.

### 추론과 판단

- 두 번째 copy는 renderer에 안정적으로 소유된 연속 surface를 제공하고 decoder의 다음 write와 분리하기 위한 구현으로 보인다. 그러나 그 설계 의도는 코드에 계약으로 문서화되어 있지 않다.
- pointer swap을 안전하게 하려면 최소한 `writable`, `published`, `render-owned/recyclable` slot 상태와 전이 규칙이 필요하다. latest index 하나만으로는 decoder가 renderer 사용 중 slot을 재사용하지 않는다는 보장이 부족하다.
- `sync()` 반환 뒤 renderer가 surface pointer를 즉시 소비 완료하는지, 다음 sync까지 보관하는지에 따라 이전 front buffer를 재사용할 수 있는 시점이 달라진다. 이 경계를 먼저 확인해야 한다.
- padded native stride를 그대로 surface에 게시할 수 있다면 첫 번째 row copy도 줄일 수 있지만, renderer가 arbitrary stride와 native buffer 수명을 지원한다는 증거가 필요하다.
- alpha 없는 format은 의미 없는 alpha byte를 읽지 않도록 `alphaIgnored`를 설정하는 것이 우선이다. 실제 blend 경로가 요구할 때만 한 번의 명시적 premultiplication/format conversion을 수행해야 한다.

## 구현 방향

1. `RenderSurface::data`를 누가 소유하고 어느 시점까지 읽는지 먼저 문서화한다. sync, draw/task 준비, renderer 완료와 loader 파괴 사이의 수명 경계를 확인한다.
2. Apple에 slot 상태를 도입한다. decoder는 `writable` slot만 채우고 release/acquire 의미로 `published`를 갱신하며, sync는 published slot을 front surface로 교체한다.
3. 이전 front pointer는 renderer가 더 이상 읽지 않는 안전한 시점에만 free slot로 돌린다. renderer 완료 신호가 없다면 최소한 다음 안전한 frame boundary 또는 ref-counted frame handle이 필요하다.
4. resize·source 변경 시에는 기존 크기의 slot을 즉시 재사용하지 않는다. 모든 reader가 빠져나온 뒤 old pool을 해제하고 새 pool을 만든다.
5. row stride가 packed이면 native→slot copy와 slot→surface copy 중 후자를 제거한다. padded stride를 surface가 지원한다면 별도 단계에서 첫 번째 copy 제거도 계측한다.
6. `no new frame`, pause, seek, EOS, loop, unload 중 sync 동작을 명시하고 마지막 정상 front frame을 유지할지 결정한다.
7. opaque native format은 `alphaIgnored`와 실제 channel layout을 함께 검증한다. format conversion이 필요한 경우 alpha를 255로 채우고 premultiplication 여부를 surface metadata와 일치시킨다.
8. Android·Windows·Linux는 main에 backend가 들어온 뒤 동일 계약을 적용한다. platform별 native surface가 CPU-addressable하지 않다면 GPU texture interop과 CPU pointer swap을 별도 설계로 둔다.

## 초심자 시작 가이드

직접 pointer swap을 구현하기보다 계측·재현 하위 작업부터 시작하는 것을 권장한다.

1. Apple `_push()`와 `sync()`에 debug-only copy byte/frame counter와 timing을 추가한다.
2. 고정 해상도 영상에서 초당 copy 횟수와 bytes, `_push()`/`sync()` p50·p95 시간을 기록한다.
3. renderer가 `surface.data`를 참조하는 시작·종료 지점을 따라가 수명 sequence diagram을 작성한다.
4. decoder thread가 빠르고 renderer가 느린 상황, pause/seek/unload 반복을 재현하는 작은 stress test를 만든다.
5. alpha byte가 0 또는 임의 값인 opaque frame fixture로 결과가 투명해지지 않는지 확인한다.

## 위험/검증

- ThreadSanitizer/AddressSanitizer로 빠른 seek, 반복 load/unload, 재생 중 파괴와 resize를 장시간 반복한다.
- decoder producer가 renderer보다 빠른 경우 slot overwrite, tearing, frame 순서 역전과 deadlock을 확인한다.
- new frame이 없는 sync가 pointer를 불필요하게 바꾸거나 마지막 frame을 지우지 않는지 확인한다.
- width×4보다 큰 stride, 홀수 width, 해상도 전환과 빈 frame을 포함한다.
- ARGB/ABGR channel 순서, opaque alpha, straight/premultiplied 입력을 구분한 color fixture로 pixel 결과를 검증한다.
- software·OpenGL·WebGPU renderer가 front pointer를 보관하는 기간을 각각 확인한다.
- sanitizer가 잡지 못하는 시각 race를 high-contrast frame 교대 영상과 frame checksum으로 탐지한다.
- 최적화 전후 native→CPU, CPU→surface copy 횟수·bytes/frame, CPU time, dropped frame과 memory peak를 같은 장비에서 비교한다.
- Apple·Android·Windows·Linux 결과를 별도 표로 보고하고, 구현이 없는 platform은 완료로 표시하지 않는다.
