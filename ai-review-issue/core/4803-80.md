## 이슈 요약

불투명한 노란 배경 위에 파란색에서 투명으로 alpha가 줄어드는 linear gradient를 놓고 `Normal`과 `Multiply`를 적용하면 CPU, GL, WebGPU가 서로 다른 그림을 만든다. 이슈는 브라우저 canvas 결과를 비교 기준으로 제공하며 W3C/PDF compositing 규칙과 다르다고 보고한다.

핵심은 blend 함수와 alpha 합성의 순서다. blend mode는 source와 backdrop의 **색**을 먼저 섞고, 그 결과를 source alpha에 따라 backdrop 위에 source-over로 합성해야 한다. 투명 쪽 끝에서 source alpha가 0이면 어떤 blend mode라도 원래 backdrop이 그대로 남아야 한다. 현재 GPU gradient shader는 source 색을 alpha로 backdrop과 먼저 `mix`한 다음 그 값을 blend 함수에 전달하고 있어 이 불변식을 깨뜨린다.

## main 코드 조사

[W3C Compositing and Blending Level 1](https://www.w3.org/TR/compositing-1/#generalformula)은 먼저 `Cs = (1 - αb) × Cs + αb × B(Cb, Cs)`로 blend를 적용하고, 다음 단계에서 Porter-Duff 계수로 composite하라고 정의한다. [simple source-over](https://www.w3.org/TR/compositing-1/#simplealphacompositing)는 premultiplied 결과를 `co = Cs × αs + Cb × αb × (1 - αs)`, 결과 alpha를 `αo = αs + αb × (1 - αs)`로 정의한다. [Multiply](https://www.w3.org/TR/compositing-1/#blendingmultiply)는 `B(Cb, Cs) = Cb × Cs`다.

[현재 GL linear/radial gradient blend header](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/gpu_engine/gl/tvgGlShaderSrc.cpp#L600-L667)는 gradient texture의 premultiplied RGB를 alpha로 나눈 뒤, `mix(d.Dc, d.Sc, d.Sa * d.So)`로 source를 backdrop에 먼저 섞는다. `d.Sa`도 destination alpha와 1 사이에서 미리 섞고 `postProcess()`는 아무 작업 없이 blend 결과를 반환한다.

[현재 WebGPU linear header](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/gpu_engine/wg/tvgWgShaderSrc.cpp#L285-L326)와 [radial header](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/gpu_engine/wg/tvgWgShaderSrc.cpp#L329-L376)도 `data.Sc`와 `data.Sa`를 먼저 destination과 `mix`하고 `postProcess()`에서 그대로 반환한다. source alpha가 0이면 blend 함수에 `Sc = Dc`가 들어가므로 Multiply는 `B(Dc, Dc) = Dc²`를 만들 수 있다. 투명 source가 backdrop을 바꾸는 현상을 코드와 수식으로 설명할 수 있다.

[CPU gradient dispatch](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/cpu_engine/tvgSwRaster.cpp#L1383-L1413)는 blend mode가 있을 때 fill sampler에 `opBlendPreNormal`을 넘겨 먼저 source-over 결과를 만든 다음 `surface->blender`를 호출한다. [`opBlendPreNormal`](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/cpu_engine/tvgSwCommon.h#L447-L450)은 premultiplied source와 남은 destination 기여를 더한다. [`blendMultiply()`](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/src/renderer/cpu_engine/tvgSwBlendOp.cpp#L142-L152)는 destination을 unpremultiply한 뒤 channel multiply와 자체 premultiply helper를 수행한다. GPU와 다른 순서이며, 이슈의 CPU 결과도 표준 oracle과 pixel 단위로 비교해야 한다.

[GL gradient 테스트](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/test/testGlEngine.cpp#L271-L334)는 GLES shader 오류 때문에 `Normal` 이외 mode를 주석 처리한 구간이 있고, 활성 경로도 `draw()`/`sync()` 성공만 확인한다. [WebGPU 테스트](https://github.com/thorvg/thorvg/blob/b07c83fe13a33b85a38350bfaa708be772a3e9ea/test/testWgEngine.cpp#L305-L330) 역시 alpha가 다른 gradient stop을 사용하지만 pixel RGBA를 assertion하지 않는다. 현재 테스트는 shader가 컴파일되고 호출이 성공하는지는 보지만 계산 결과가 맞는지는 보지 못한다.

[PR #4812](https://github.com/thorvg/thorvg/pull/4812)는 GL/WG gradient에서 사전 `mix`를 제거하고 blend 결과를 `postProcess()`에서 `d.Sa * d.So`만큼 destination과 섞도록 바꾼다. maintainer는 GPU root issue가 해결됨을 확인했지만 PR은 아직 open이다. 자동 pixel inspector는 GL/WG 각각 기준 이미지 1건 변경을 보고했고, review에는 실제 RGBA assertion 부재와 GL radial blend shader buffer 상한 계산이 모든 mode의 최대 문자열을 보장하는지에 대한 우려가 남아 있다.

## 원인 분석

### 확인된 사실

- 재현은 같은 source/backdrop/gradient에서 CPU, GL, WebGPU가 서로 다른 결과를 낸다.
- 표준은 blend color 계산을 먼저 하고 Porter-Duff composite를 뒤에 적용한다.
- source alpha가 0인 source-over 결과는 backdrop 색과 alpha를 보존해야 한다.
- current main의 GL/WG gradient shader는 source color와 alpha를 destination에 미리 섞은 뒤 blend 함수를 실행한다.
- CPU gradient는 `opBlendPreNormal`과 `surface->blender`를 조합해 GPU와 다른 처리 순서를 사용한다.
- GL/WG 단위 테스트는 실제 pixel 색·alpha를 검증하지 않는다.
- GPU 선행 PR은 open·unmerged이며 GPU 현상 개선은 확인됐지만 회귀 테스트와 shader buffer 검토가 남았다.

### 추론과 판단

- **GPU의 직접 원인은 blend와 composite 순서의 역전이다.** alpha를 적용해 backdrop과 섞은 값을 `B(Cb, Cs)`의 source로 사용하면 blend 함수가 원래 source 색이 아닌 이미 합성된 색에 적용된다.
- `αs = 0` 경계가 가장 강한 oracle이다. 현재 GPU식에서는 `Sc = Dc` 뒤 Multiply가 `Dc²`를 만들지만 표준 source-over에서는 source 기여가 0이므로 output은 반드시 `Dc`다.
- PR #4812의 방향은 수식에 부합하지만 `mix(vec4(Dc, Da), R, Sa × So)`에서 `R`의 alpha와 RGB 표현이 각 blend fragment에서 일관되는지 모든 mode로 확인해야 한다. 한 재현이 맞아졌다는 사실만으로 non-separable mode까지 증명되지는 않는다.
- CPU는 사전 source-over 결과를 blender에 전달하므로 표준과 동일하다고 단정할 수 없다. 정수 rounding, premultiply helper, coverage와 opacity가 source alpha에 중복 적용되는지 계산표로 분리해야 한다.
- 기준 이미지 갱신만으로는 오류를 정답으로 고정할 위험이 있다. 표준 수식에서 계산한 소수 RGBA oracle 또는 독립 reference renderer가 필요하다.

## 구현 방향

1. 색 표현 계약을 먼저 문서화한다. gradient texture sample, `FragData.Sc`, blend 함수 반환 `R`, framebuffer의 RGB가 각각 straight인지 premultiplied인지와 `Sa`, paint opacity `So`, coverage의 적용 지점을 명시한다.
2. 공통 알고리즘을 “unpremultiplied source/backdrop으로 `B(Cb, Cs)` 계산 → source alpha/opacity/coverage 적용 → source-over composite → 필요하면 저장 형식으로 premultiply” 순서로 고정한다.
3. GL과 WebGPU의 linear/radial header를 같은 식으로 바꾸고, image/scene/solid header와 차이가 의도적인지 확인한다. 같은 `postProcess` 수식을 중복한다면 생성 helper나 명확한 parity comment로 drift를 줄인다.
4. CPU에서 gradient sample 직후와 blender 직전의 실제 packed RGBA를 작은 값으로 추적한다. `αs = 0, 0.5, 1`, `αb = 0, 0.5, 1` 표를 만들고 W3C 식과 비교해 필요한 경우 `opBlendPreNormal`/blender 순서를 수정한다.
5. PR #4812의 GL buffer 크기는 선택된 header/helper/blend fragment의 실제 길이에서 계산하거나 모든 후보의 `max`를 사용한다. 고정 상수는 compile-time/debug assertion으로 `snprintf` 결과가 buffer보다 작은지 검사한다.
6. 기존 engine tests에 offscreen pixel readback을 추가한다. `draw/sync == Success`와 별개로 gradient 시작·중간·투명 끝의 RGB와 alpha를 허용 오차 안에서 비교한다.
7. pixel inspector 기준 이미지는 수식 기반 regression이 통과한 뒤에만 갱신하고 변경 이유를 alpha/composite 계약으로 기록한다.

## 위험/검증

- linear와 radial gradient에서 stop alpha `0`, `1`, `0→1`, `1→0`, 중간 alpha를 검증한다.
- source alpha 0에서는 모든 blend mode가 backdrop RGBA를 정확히 보존하는지 확인한다.
- source alpha 1과 불투명 backdrop에서는 각 W3C blend 공식의 순수 색 결과를 확인한다.
- backdrop alpha `0`, `0.5`, `1`을 나눠 결과 alpha `αo`와 premultiplied RGB를 검사한다.
- paint opacity, antialias coverage, mask, scene opacity가 source alpha에 한 번만 적용되는지 조합 테스트한다.
- Normal, Multiply, Screen, Overlay, Dodge/Burn, Hard/SoftLight, Hue/Saturation/Color/Luminosity를 separable/non-separable로 나눠 검증한다.
- CPU의 8-bit rounding과 GPU float 결과 사이 허용 오차를 명시하되 구조적 색 차이를 tolerance로 숨기지 않는다.
- GL, GLES/WebGL, WebGPU에서 linear/radial shader가 모두 compile되는지 확인하고 `snprintf` truncation을 assertion한다.
- engine test에 pixel readback이 어려우면 작은 1×N reference surface 또는 pixel inspector fixture를 CI에 고정한다.
- 기존 535개 backend 이미지와 1,640개 compliance 이미지 전체를 비교하고 의도한 차이만 승인한다.
